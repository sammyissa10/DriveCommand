<task type="auto">
  <name>Task 1: Create mobile AddressInput component</name>
  <files>apps/mobile/components/owner/AddressInput.tsx</files>
  <action>
Create a new React Native component `AddressInput` with the following:

**Props interface:**
```ts
interface AddressInputProps {
  value: string
  onChangeText: (text: string) => void
  onAddressSelect: (result: { formatted_address: string; latitude: number; longitude: number }) => void
  placeholder?: string
  error?: string
}
```

**Implementation details:**
- Use `TextInput` for the input field. Style it to match CreateLoadSheet's existing input style: `bg-slate-700 border border-slate-600 rounded-xl px-4 py-3 text-white text-sm`. If `error` prop is set, use `border-red-500` instead.
- Debounce input by 500ms using a `useRef<ReturnType<typeof setTimeout>>` pattern (same as web component). Min 3 chars to trigger search.
- Fetch from the geocoding proxy using absolute URL: `${process.env.EXPO_PUBLIC_API_URL || 'http://10.0.2.2:3000'}/api/geocoding/autocomplete` with POST body `{ query }`.
- No auth header needed for this endpoint (it's a public geocoding proxy).
- Display suggestions in a `FlatList` rendered directly below the input (not a modal/overlay -- use absolute positioning with `zIndex: 50`). Wrap the entire component in a `View` with `position: 'relative'` and `zIndex` so dropdown overlays content below.
- Each suggestion row: `Pressable` with min height 48px (touch target), padding 12px horizontal + 14px vertical, `border-b border-slate-600` separator. Text: `text-white text-sm`. Active state: `bg-slate-600`.
- Show `ActivityIndicator` (small, color="#0ea5e9") inside the input field (absolute positioned right side) while loading.
- Empty state (query >= 3 chars, not loading, results empty): show single row "No results found" in `text-slate-400 text-sm`.
- Error state (fetch failed): show single row "Search unavailable" in `text-slate-400 text-sm`. User can still type manually.
- On suggestion tap: call `onAddressSelect({ formatted_address, latitude, longitude })`, call `onChangeText(formatted_address)`, hide dropdown.
- On blur or when user taps outside: hide dropdown (use a simple `isOpen` state that closes on selection; the parent ScrollView's `keyboardShouldPersistTaps="handled"` will handle the rest).
- `autoCorrect={false}`, `autoCapitalize="none"` on TextInput.

Run `npx tsc --noEmit` from `apps/mobile` to verify the component compiles.
Visual check: import and render in CreateLoadSheet temporarily to verify it displays correctly on Android emulator.
  </verify>
  <done>AddressInput component exists, renders a TextInput with autocomplete dropdown, calls geocoding proxy, returns selected address with coordinates. Touch targets are minimum 48px. Loading, empty, and error states are handled.</done>

  onChangeText={(v) => setField('origin', v)}

Remove the wrapping `<TextInput>` and the error display below it (AddressInput does not display errors itself, so keep the error `<Text>` below).

Actually, looking at the pattern: AddressInput does NOT render the error text. Keep the existing error display `{errors.origin && <Text>...}` below the AddressInput. The `error` prop on AddressInput only controls border color.

5. The coordinate state is stored for future use but NOT sent in the createLoad mutation. The current API at `/api/mobile/owner/loads` accepts `origin` and `destination` as strings only. Sending lat/lng to the API is a future enhancement, not part of this plan.
