  <action>
Create a single read-only TypeScript script that scans EVERY Prisma model and diffs it against the live database. Use diagnose-trip-column-drift.ts as the structural reference — same imports (PrismaClient from generated/prisma/client, PrismaPg from @prisma/adapter-pg, Pool from pg), same DATABASE_URL env check, same file-based schema parsing approach, same information_schema.columns query pattern.

Required behavior:

1. **Parse ALL models from schema.prisma** (not just Trip):
   - Read apps/web/prisma/schema.prisma via fs.readFileSync
   - Find every `model XXX {` ... `}` block using line scanning + brace depth tracking (same approach as the existing script, but loop over every model rather than only `model Trip`)
   - For each model, capture: model name, @@map value (default = the model name verbatim — Prisma maps PascalCase models to PascalCase tables unless @@map overrides), and all scalar fields
   - Scalar types whitelist: String, Int, Float, Boolean, DateTime, Decimal, Json, Bytes, BigInt — skip any field whose base type (with `?` and `[]` stripped) is not in this set (those are relations)
   - For each scalar field, extract: prismaName, prismaType (including `?` / `[]`), physicalColumn (= @map("xxx") value if present, else the prismaName verbatim — Prisma does NOT auto-snake-case)
   - Also capture native type hints from @db.Uuid, @db.Text, @db.Decimal(p,s), @db.VarChar(n) when present — needed for accurate Postgres type mapping in the SQL draft

2. **Query the live DB once per mapped table**:
   - Build a unique list of candidate table names from all @@map values (and bare model names for those without @@map)
   - For each candidate, run: `SELECT column_name, data_type, udt_name, is_nullable FROM information_schema.columns WHERE table_schema = 'public' AND table_name = $1 ORDER BY ordinal_position`
   - Track which candidates returned rows (= table exists) and which did not (= MODEL HAS NO TABLE IN DB)
   - Do NOT auto-fall-back to snake_case or PascalCase variants — the @@map value (or model name) is authoritative. If it doesn't exist, flag it.

3. **Compute per-model diff**:
   - For each model where the table exists: `missingInDb = schemaPhysicalColumns - liveColumns`, `extraInDb = liveColumns - schemaPhysicalColumns`
   - Only emit a block in the console report for models with non-empty drift (skip clean models entirely — keep output focused)
   - Output format per drifted model (exact format requested):
     ```
     MODEL: Trip (table: dispatches)
       MISSING IN DB: deleted_at (TIMESTAMPTZ?), deleted_by_id (String? @db.Uuid → UUID?)
       EXTRA IN DB: (none)
     ```
   - For "MISSING IN DB" entries, render: `<physicalColumn> (<prismaType> → <pgType>?)` where pgType is the mapped Postgres type and the trailing `?` indicates nullable (always nullable in this draft)
   - For "EXTRA IN DB" entries, render: `<column_name> (<data_type>)` — informational only, never added to the SQL draft

4. **Prisma → Postgres type mapping** (for the SQL draft):
   - String → TEXT (default), or UUID if @db.Uuid, or VARCHAR(n) if @db.VarChar(n)
   - Int → INTEGER
   - BigInt → BIGINT
   - Float → DOUBLE PRECISION
   - Decimal → NUMERIC (use NUMERIC(p,s) if @db.Decimal(p,s) hint present)
   - Boolean → BOOLEAN
   - DateTime → TIMESTAMPTZ
   - Json → JSONB
   - Bytes → BYTEA
   - Implement as a single `prismaTypeToPgType(prismaType: string, nativeHint?: string)` helper

5. **Generate consolidated SQL draft**:
   - Build a single string with this exact shape:
     ```
     -- CONSOLIDATED FIX MIGRATION (draft — review before applying)
     -- Generated by: apps/web/scripts/audit/full-schema-drift-scan.ts
     -- Generated at: <ISO timestamp>
     -- DO NOT APPLY without reviewing each ALTER TABLE statement.
     BEGIN;
     ALTER TABLE public."<table>" ADD COLUMN IF NOT EXISTS "<column>" <pgType> NULL;
     -- (one line per missing column, grouped by table with a comment header per table)
     COMMIT;
     ```
   - Use `IF NOT EXISTS` on every ADD COLUMN (idempotent safety)
   - Quote both table and column names with double-quotes to handle PascalCase
   - Every added column is `NULL` (nullable) — per the constraint, no NOT NULL anywhere
   - Write the string to `apps/web/scripts/audit/417-DRIFT-FIX-DRAFT.sql` via fs.writeFileSync (resolve path relative to process.cwd() = apps/web)
   - Also print the same SQL to stdout at the end of the run

6. **Summary footer** (always print, even with zero drift):
   ```
   ════════════════════════════════════════════════════════════
     SUMMARY
   ════════════════════════════════════════════════════════════
     Models scanned: <total>
     Models with drift: <X>
     Models with missing tables: <N>
     Total columns missing in DB: <Y>
     Total extra columns in DB: <Z>
     SQL draft written to: apps/web/scripts/audit/417-DRIFT-FIX-DRAFT.sql
   ```

7. **Read-only guarantees** (enforce in code):
   - NEVER call prisma.$executeRaw / $executeRawUnsafe
   - NEVER write to schema.prisma or anything in prisma/migrations/
   - Only DB call is the SELECT against information_schema.columns
   - Only file writes are: apps/web/scripts/audit/417-DRIFT-FIX-DRAFT.sql

8. **Run command** in the file header comment block: `npx tsx --env-file=.env.local scripts/audit/full-schema-drift-scan.ts` (run from apps/web)

9. **Exit codes**: 0 on completion regardless of drift count (diagnostic, not gate). 1 only on script error (DB connection failure, schema parse error, file write failure).

10. **Cleanup**: `prisma.$disconnect()` and `pool.end()` in a `.finally()` block (same pattern as diagnose-trip-column-drift.ts).
