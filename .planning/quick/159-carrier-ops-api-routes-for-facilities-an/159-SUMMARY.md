## What Was Built

**Facilities (3 files):**
- `listFacilities`: orgId-scoped query with facilityType filter, name search, and optional proximity search via raw SQL haversine formula (`$queryRaw` on the `facilities` table)
- `softDeleteFacility`: Sets `facilityType` to `inactive_{originalType}` — workaround for missing `active` column
- Full CRUD routes at `/api/v1/carrier/facilities` and `/api/v1/carrier/facilities/[id]`
- `contactEmail` validated with `.email()` when provided

**Route Templates (3 files):**
- `listRouteTemplates`: Includes `_count.stops` and computes `nextDispatchDate` via `computeNextOccurrence` for each template with a `recurrenceRule`
- `computeNextOccurrence`: Inline RRULE parser supporting FREQ=DAILY/WEEKLY/MONTHLY with BYDAY, BYMONTHDAY, INTERVAL, UNTIL, COUNT
- `getRouteTemplate`: Returns ordered stops with facility name/city/state via nested `include`
- `updateRouteTemplate`: Includes prominent comment that edits do NOT retroactively modify already-generated dispatches
- `softDeleteRouteTemplate`: Sets `active = false` (RouteTemplate already has the column)
- Full CRUD routes at `/api/v1/carrier/route-templates` and `/api/v1/carrier/route-templates/[id]`

**Dispatch Generator (2 files):**
- `expandSchedule`: Expands all matching dates between today and a through-date from an RRULE string
- Deduplication: Skips dates where a dispatch from this template already exists (day-range query)
- Required FK validation: Skips dates where template lacks `defaultDriverId` or `defaultTruckId` (both non-nullable on `CarrierDispatch`)
- Conflict detection: Checks if the default driver or truck has another dispatch on the same day; sets `needs_assignment=true` in notes when conflict found
- Dispatch numbering: Counts existing `[AUTO-GENERATED]` dispatches via `$queryRaw` to produce sequential `DC-YYYY-NNNNN` numbers stored in `notes` (schema workaround)
- Stop cloning: Creates `CarrierStop` records for each `RouteTemplateStop`, storing address snapshot in `notes` JSON
- Load creation: When template has `contractId`, creates a `CarrierLoad` with rate/fuel surcharge from contract
- POST `/api/v1/carrier/route-templates/[id]/generate` accepts `{ generate_through_date: "YYYY-MM-DD" }`, returns `{ dispatches_created, skipped_existing, errors }`

## Deviations from Plan

None — plan executed exactly as written. Schema limitation workarounds were pre-documented in the plan's `<schema_notes>` and `<additional_context>`.

## Decisions Made

1. **facilityType prefix soft-delete** — `softDeleteFacility` prepends `inactive_` to `facilityType` since `CarrierFacility` has no `active` column. The `listFacilities` WHERE clause excludes rows where `facilityType` starts with `inactive_`. Code comments point to migration 015.

2. **notes-field workarounds for CarrierDispatch** — `dispatchNumber`, `isAutoGenerated`, and `needsAssignment` are stored as a structured prefix string (`[AUTO-GENERATED] dispatch_number=DC-2026-00001 needs_assignment=true`) in the `notes` field. Code comments recommend adding proper columns in migration 015/016.

3. **Address snapshot in CarrierStop.notes** — Facility address data (addressLine1, city, state, zip, lat, lng) is serialized as `{ address_snapshot: {...} }` JSON into `CarrierStop.notes` at generation time. This prevents stop records from becoming stale if a facility is later edited or deleted.

4. **No external RRULE library** — The RRULE parser (`computeNextOccurrence` and `expandSchedule`) is implemented inline, keeping the dependency footprint zero. Supports the three most common patterns for trucking (daily recurring, specific weekdays, specific month days). Complex rules fall back to returning `null`/empty with a warning log.
