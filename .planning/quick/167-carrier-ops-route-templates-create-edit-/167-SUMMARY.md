# Phase quick-167 Plan 01: Route Templates Create/Edit Summary

**One-liner:** Route Templates CRUD with two-panel StopBuilder form, yellow edit banner, RRULE schedule display, atomic server action, and DispatchPreview with generate-on-demand.

## What Was Built

### Task 1: Route Templates list page + RouteTemplateList component

**`apps/web/src/app/(owner)/carrier/templates/page.tsx`** — Thin server component. Validates session, renders `<RouteTemplateList />`.

**`apps/web/src/components/carrier/templates/RouteTemplateList.tsx`** — Client component with:
- Fetches active and optionally inactive templates via `GET /api/v1/carrier/route-templates`
- Fetches clients via `GET /api/v1/carrier/clients` and builds a `clientMap` for name display
- 8-column table: Template Name (link), Client, Contract, Schedule, Equipment (badge), Stops count, Active (Switch toggle), Next Dispatch
- `formatRecurrenceRule()` helper converts RRULE strings (DAILY/WEEKLY/MONTHLY) to human-readable format (e.g. "MWF 06:00 CT", "Daily 08:00 ET", "Monthly 1st,15th")
- Active toggle calls `PATCH /api/v1/carrier/route-templates/[id]` with optimistic UI update + sonner toast
- Search filters by template name client-side
- "Show inactive" checkbox refetches inactive templates

### Task 2: RouteTemplateForm + DispatchPreview + create/edit pages

**`apps/web/src/actions/carrier/save-route-template.ts`** — `'use server'` action:
- Validates session + required fields (name, clientId, equipmentType, scheduleType)
- Validates `recurrenceRule` starts with `FREQ=` if provided
- Edit mode: `prisma.$transaction` updates template + deletes/recreates all stops
- Create mode: `prisma.$transaction` creates template + stops via `createMany`
- Returns `{ success, templateId?, error? }`

**`apps/web/src/components/carrier/templates/RouteTemplateForm.tsx`** — Two-panel form:
- Left panel: all metadata fields (templateName, clientId, contractId, scheduleType, recurrenceRule with FREQ= validation, timezone, departure time, equipmentType, reefer temp range, maxWeightLbs, commodityDescription, defaultDriverId/TruckId UUIDs, autoGenerateDaysAhead, notes)
- Right panel: `<StopBuilder stops={stops} onChange={setStops} mode="template" />` — StopBuilder components NOT modified
- Edit mode: yellow AlertTriangle warning banner at top
- Contracts reload when client changes via `GET /api/v1/carrier/contracts?client_id=X`
- On submit: calls `saveRouteTemplate` server action, redirects to edit page (create) or refreshes (edit)

**`apps/web/src/components/carrier/templates/DispatchPreview.tsx`** — Client component:
- Fetches existing dispatches via `GET /api/v1/carrier/dispatches?route_template_id=[id]&pageSize=50` on mount
- "Regenerate" button calls `POST /api/v1/carrier/route-templates/[id]/generate` (14-day window) then refetches
- Shows generate result summary (created / skipped / errors)
- Skeleton loading state (4 rows of pulsing bars)
- Table columns: Date, Day of Week, Dispatch ID (truncated), Driver (truncated), Truck (truncated)

**`apps/web/src/app/(owner)/carrier/templates/new/page.tsx`** — Create shell with back link and `<RouteTemplateForm />`.

**`apps/web/src/app/(owner)/carrier/templates/[id]/page.tsx`** — Edit shell:
- Server component fetches template via `getRouteTemplate(tenantId, id)`
- Maps DB `RouteTemplateStop` fields to `StopBuilderStop` format for initialData
- Renders `<RouteTemplateForm initialData={...} templateId={id} />` + `<DispatchPreview templateId={id} />`
