# v5.0 DriveCommand Mobile — Milestone Roadmap

**Status:** Planned — not started
**Target:** 9-10 weeks from kickoff
**Phases:** 29-39 (11 phases, 27 plans)

---

## Milestone Goal

Extend DriveCommand into production-ready native iOS and Android applications. Driver and owner portals are rebuilt as native tab-navigated experiences using React Native + Expo. The existing Next.js web app and its API routes serve as the mobile backend with zero changes. No sysadmin portal on mobile. Ships to both the Apple App Store and Google Play Store.

---

## Architecture Decisions (Locked)

| Decision | Choice | Reason |
|---|---|---|
| Framework | React Native 0.76 + New Architecture | JSI/Fabric eliminates bridge jank; required for concurrent React 19 |
| Build tooling | Expo SDK 52 + Expo Router v4 | File-based routing mirrors Next.js App Router; EAS handles native builds |
| Monorepo | Turborepo | Shared packages between web and mobile; one turbo run build |
| Styling | NativeWind v4 | Tailwind class syntax on RN; design muscle memory transfers |
| Auth storage | react-native-mmkv | 10x faster than AsyncStorage; encrypted; biometric-ready |
| Backend | Existing Next.js API (unchanged) | All /api/* routes serve mobile via Bearer token auth |
| OTA updates | EAS Update | Ship JS fixes without App Store review |
| Build/submit | EAS Build + EAS Submit | Cloud build machines; no Xcode on CI |

## Scope

### In scope (v1.0 mobile)

**Driver portal:**
- Login + session management
- Dashboard (active load, HOS snapshot, alerts)
- Loads list (active + completed) + load detail + status updates
- HOS duty status logging + daily log timeline
- Incident reporting with GPS + photo
- Background GPS reporting (→ existing /api/gps/report)
- Push notifications (dispatch alerts, HOS warnings)
- Document viewer + upload (→ existing S3 multipart API)
- Driver messaging (fleet messages)
- Offline mutation queue (flushes on reconnect)

**Owner portal:**
- Login + session management (shared auth, role-based routing)
- Dashboard (KPIs, active loads, driver status)
- Loads management (list, create, assign)
- Driver management (status, compliance, contact)
- Live map (react-native-maps, vehicle markers, detail)
- Fleet messaging (compose, broadcast, thread)

### Explicitly out of scope (mobile v1.0)

- Sysadmin portal — desktop-only by design
- Payroll processing — complex multi-step, desktop workflow
- Invoice creation — detailed line-item entry, desktop workflow
- Route/lane analytics — heavy data tables, desktop workflow
- IFTA reporting — accountant workflow, desktop only
- AI document reading — file upload review, desktop workflow
- Expense template management — configuration, desktop only
- QuickBooks sync — integration configuration, desktop only

These remain fully functional on the web app.

## Key Technical Notes

### Auth adapter
The existing `/api/auth/login` returns a JWT in a session cookie. On mobile, add JSON body token return: `res.json({ token, user })`. Mobile reads token from JSON, ignores cookie. Zero breaking change to web.

### Shared packages
- `packages/types` — TypeScript interfaces (Truck, Driver, Load, Route, User, Tenant)
- `packages/validation` — Zod schemas moved from `src/lib/validations/*`
- `packages/api-client` — Typed fetch with `Authorization: Bearer <token>` header

### GPS tracking
Existing `/api/gps/report` and `/api/gps/locations` routes work as-is. Mobile sends same payload (latitude, longitude, speed, token). No backend changes needed.

### Push notifications
One new endpoint needed: `/api/push-tokens` (POST — upsert Expo push token by userId+platform). One new DB table: `PushToken`. Owner fleet messaging action extended to call `sendPushNotification(driverId)` after saving the message.

### OTA updates
After Week 8, any JS-only fix (bug fix, text change, non-native behavior) ships via `eas update --branch production` in ~2 minutes with zero App Store review. Only changes that touch native code (new Expo modules, permissions, native APIs) require a full store submission.
