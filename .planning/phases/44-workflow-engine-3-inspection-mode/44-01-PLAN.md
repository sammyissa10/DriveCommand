**Change 1: Add VEHICLE_INSPECTION to PlaybookCategory enum**

In `apps/web/prisma/schema.prisma`, find the `PlaybookCategory` enum (currently `ONBOARDING`, `SAFETY`) and add `VEHICLE_INSPECTION` as a new value. The full enum should read:

```
enum PlaybookCategory {

  SAFETY
  OPERATIONS
```

Note: check the actual current enum values first — research noted `ONBOARDING | SAFETY | OPERATIONS | COMPLIANCE | PARTNER | CUSTOM`. Add `VEHICLE_INSPECTION` to that list.

**Change 2: Make stepTemplateId nullable on StepInstance**

In `apps/web/prisma/schema.prisma`, find the `StepInstance` model. Change:
```
stepTemplateId     String       @db.Uuid
```
to:
```
stepTemplateId     String?      @db.Uuid
```

Also update the relation line to reflect optional:
```
stepTemplate     StepTemplate?    @relation(fields: [stepTemplateId], references: [id], onDelete: Restrict)
```

And keep the `@@index([stepTemplateId])` — it works with nullable columns.

**Migration file:**

Create `apps/web/prisma/migrations/20260424100001_workflow_engine_inspection_mode/migration.sql`:

```sql
-- Migration: Phase 44 — Inspection Mode schema changes
-- 1. Add VEHICLE_INSPECTION to PlaybookCategory enum
-- 2. Make StepInstance.stepTemplateId nullable (for ad-hoc APPROVAL steps)

-- 1. Add enum value (PostgreSQL enum ALTER)
ALTER TYPE "PlaybookCategory" ADD VALUE IF NOT EXISTS 'VEHICLE_INSPECTION';

-- 2. Make stepTemplateId nullable
ALTER TABLE "StepInstance" ALTER COLUMN "stepTemplateId" DROP NOT NULL;
```

Note: PostgreSQL enum `ADD VALUE` is transactional-safe with `IF NOT EXISTS`. Do not wrap in a transaction — Prisma handles migration transactions.

After writing both files, run:
```
cd apps/web && npx prisma migrate deploy && npx prisma generate
```

If migration deploy fails due to enum in transaction, run the SQL manually via Supabase MCP:
```sql

ALTER TABLE "StepInstance" ALTER COLUMN "stepTemplateId" DROP NOT NULL;
```
Then run `npx prisma generate` to regenerate the client.
