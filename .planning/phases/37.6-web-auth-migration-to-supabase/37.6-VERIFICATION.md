## Summary

Phase 37.6 achieved its stated goal. All 7 observable truths verified against the actual codebase.

Security claims (role, tenantId, isSystemAdmin, permissions) are written to app_metadata at user creation and read from app_metadata in all 6 auth files. No security claim is read from user_metadata anywhere in the auth layer.

apps/web/src/lib/auth/supabase.ts exists at 199 lines, exports all required functions (getSession, requireAuth, requireRole, isSystemAdmin, getCurrentUser, getRole, requirePermission, SessionData), and is imported by 72 source files. The three old fragmented modules (session.ts, server.ts, require-permission.ts) are deleted with zero remaining imports pointing to them. AUTH_SECRET is absent from all source, env, and doc files. All stale session decrypt and AES comments are gone from source. TypeScript compiles with zero errors.

One item warrants attention before shipping to production: existing users created before this migration may have claims only in user_metadata, not app_metadata. The new read path returns empty role/tenantId for those users. A backfill via Supabase Admin API is likely required.
