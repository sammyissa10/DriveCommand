# Phase 34 — Plan 02: Driver Messaging Screen

## Goal
Build the fleet messaging screen where drivers view all messages from dispatchers/owners and can reply, with real-time unread badge count on the Messages tab icon.

## Prerequisites
- Plan 34-01 complete
- Phase 33-02 complete (push notifications — messages trigger push)

## Tasks

### 1. Create REST endpoints for driver messaging
File: apps/web/src/app/api/mobile/driver/messages/route.ts

GET /api/mobile/driver/messages:
```typescript
// Auth: Bearer → driverId
// Return all FleetMessages where recipientId = driverId OR isBroadcast = true
// Include driver's reply messages
// Sort by createdAt desc
// Return: FleetMessage[]
```

POST /api/mobile/driver/messages:
```typescript
// Auth: Bearer → driverId
// Body: { body: string, replyToId?: string }
// Creates FleetMessage with senderId=driverId, senderType=DRIVER
// Return: { message: FleetMessage }
```

GET /api/mobile/driver/messages/unread-count:
```typescript
// Auth: Bearer → driverId
// Return: { count: number } — messages not readAt for this driver
```

POST /api/mobile/driver/messages/mark-read:
```typescript
// Auth: Bearer → driverId
// Marks all messages as read for this driver
// Updates readAt timestamp
// Return: { success: true }
```

### 2. Extend api-client
```typescript
getMessages: (token) => apiRequest('/api/mobile/driver/messages', { token }),
sendMessage: (token, body, replyToId?) => apiRequest('/api/mobile/driver/messages', {
  method: 'POST', token, body: JSON.stringify({ body, replyToId }),
}),
getUnreadCount: (token) => apiRequest('/api/mobile/driver/messages/unread-count', { token }),
markMessagesRead: (token) => apiRequest('/api/mobile/driver/messages/mark-read', {
  method: 'POST', token,
}),
```

### 3. Build messages list screen
File: apps/mobile/app/(driver)/messages.tsx

- ScreenWrapper (not scrollable — FlatList handles it)
- FlatList of message rows (inverted: newest at bottom)
- Each row:
  - Left/right alignment based on sender (driver=right, owner=left)
  - Avatar initials circle (sender name initial, background color deterministic from name)
  - Message text (body, wrapping)
  - Timestamp (relative: "2 min ago", "Yesterday")
  - Unread dot on owner messages that haven't been read
- Text input + send button at bottom (KeyboardAvoidingView)
- Poll for new messages every 30s (useQuery refetchInterval)
- Mark all as read on screen focus (useEffect)

Message bubble component (components/driver/MessageBubble.tsx):
```typescript
// Driver's messages: right-aligned, bg-sky-600, text-white
// Owner's messages: left-aligned, bg-slate-700, text-white
// Timestamp below: text-slate-400 text-xs
// Avatar: colored circle with initial, shown only on first message in a group
```

### 4. Unread badge on Messages tab
File: apps/mobile/app/(driver)/_layout.tsx (update Messages tab)

```typescript
// useQuery for unread count (refetchInterval: 30000)
// Render badge overlay on MessageSquare icon:
<View style={{ position: 'relative' }}>
  <MessageSquare color={color} size={24} />
  {unreadCount > 0 && (
    <View className="absolute -top-1 -right-1 bg-red-500 rounded-full min-w-4 h-4 items-center justify-center">
      <Text className="text-white text-xs font-bold">
        {unreadCount > 99 ? '99+' : unreadCount}
      </Text>
    </View>
  )}
</View>
```

### 5. Send message functionality
Reply input at bottom of messages screen:
- TextInput with placeholder "Reply to dispatcher..."
- Send button (disabled when text is empty or while sending)
- On send: POST to /api/mobile/driver/messages → optimistic append to list → refresh
- Empty input after send
- Error: toast + restore input text

### 6. Handle push notification deep-link to messages
When a push notification with data.screen === 'messages' is tapped:
- Navigate to /(driver)/messages
- Screen automatically fetches latest messages and marks as read
