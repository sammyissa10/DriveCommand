**Prisma schema with InvoiceItemType/InvoiceItemUnit enums, 7 freight header fields on Invoice, and PERCENT-aware amount calculation in server action**

## Accomplishments
- Added InvoiceItemType and InvoiceItemUnit enums to schema and database via idempotent migration
- Added 7 nullable freight header fields to Invoice (BOL/PRO/PO numbers, commodity, weight, pieces, loaded miles)
- Added itemType (default OTHER) and unitType (default FLAT) to InvoiceItem — existing items unaffected
- Updated Zod validation package with enum arrays, label maps, and new freight field schemas
- Fixed server action PERCENT calculation: `amount = (qty / 100) * price` in both createInvoice and updateInvoice

- `apps/web/src/app/(owner)/actions/invoices.ts` - PERCENT calculation fix, freight field persistence in createInvoice and updateInvoice

## Decisions Made
- `itemType` defaults to `OTHER` and `unitType` defaults to `FLAT` — existing invoice items render identically with no data migration
- `loadedMiles` uses `Decimal(10,2)` consistent with the project's Decimal precision pattern for monetary/measurement fields
- PERCENT unit stores the percentage number in `quantity` (e.g., 15 for 15%) with the base amount in `unitPrice` — matches industry convention for FSC calculation
- Validation package exports const arrays and label maps to avoid enum duplication in UI components
