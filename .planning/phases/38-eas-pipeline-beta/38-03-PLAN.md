# Phase 38 — Plan 03: Beta Distribution + Testing Checklist

## Goal
Set up TestFlight external testing for iOS and Google Play Open Testing for Android, run the internal testing checklist on physical devices, and document any issues found before App Store submission.

## Prerequisites
- Plans 38-01 and 38-02 complete
- Production builds exist on EAS Build
- Physical iOS device (iPhone) and Android device available for testing

## Tasks

### 1. iOS TestFlight setup
1. Log in to App Store Connect (appstoreconnect.apple.com)
2. Create new app: "DriveCommand" with bundle ID com.drivecommand.app
3. Submit first build via `eas submit --platform ios --profile production --latest`
4. In App Store Connect → TestFlight:
   - Create external testing group: "Beta Testers"
   - Add beta testers by email (invite yourself + anyone testing)
   - Submit for Beta App Review (required for external TestFlight, 1-2 day review)
5. After approval: testers receive email with TestFlight install link

### 2. Google Play Open Testing setup
1. Log in to Google Play Console (play.google.com/console)
2. Create new app: "DriveCommand"
3. Submit .aab via `eas submit --platform android --profile production --latest`
4. In Play Console:
   - Go to Testing → Open Testing
   - Create open testing release
   - Publish to Internal Track first (instant, for your own devices)
   - Then promote to Open Testing
5. **Start the 14-day clock now** — this is mandatory before production access

Note: Google requires at least 20 testers to opt-in during the 14-day open testing period.
Post the opt-in link and recruit 20 testers (colleagues, friends with Android phones).

### 3. Device testing checklist
Run this checklist on a PHYSICAL iOS device AND a PHYSICAL Android device:

**Auth:**
- [ ] Login with driver credentials → lands on driver portal
- [ ] Login with owner credentials → lands on owner portal
- [ ] Invalid credentials → error message shown (no crash)
- [ ] Logout → returns to login screen, session cleared
- [ ] Restart app → session persists (MMKV)
- [ ] App foreground after 30 min → session still valid

**Driver — Core:**
- [ ] Dashboard loads with real data
- [ ] Loads list shows active + history tabs with correct loads
- [ ] Tapping a load → load detail loads correctly
- [ ] Status update: accept a PENDING load → confirm → status changes in DB
- [ ] Status update: start route on ACCEPTED load → confirm → status changes
- [ ] Pull-to-refresh on all screens works

**Driver — HOS:**
- [ ] HOS screen shows current status
- [ ] Tap different status → confirmation sheet → confirm → status changes
- [ ] Daily log bar updates after status change
- [ ] Clocks show correct countdown

**Driver — GPS:**
- [ ] Background GPS permission granted (both steps on iOS)
- [ ] Lock phone → wait 2 minutes → check DB for GPS pings (should exist)
- [ ] GPS status indicator shows green
- [ ] Change to OFF_DUTY → wait 5 min → verify ping interval increased

**Driver — Push Notifications:**
- [ ] Owner sends fleet message → driver device receives push notification
- [ ] Tapping notification → navigates to messages screen
- [ ] Unread badge appears on Messages tab

**Driver — Offline:**
- [ ] Enable airplane mode
- [ ] Attempt status update → "Saved offline" toast + queue count increases
- [ ] Disable airplane mode → queue flushes → status updates in DB

**Driver — Documents:**
- [ ] Documents list loads
- [ ] Tap document → detail sheet → "View Document" opens in browser
- [ ] Upload new document via file picker → progress bar → success

**Driver — Messaging:**
- [ ] Messages screen loads
- [ ] Send reply → message appears in list
- [ ] Owner's message appears in correct position (left side)

**Owner — Core:**
- [ ] Owner dashboard loads with KPIs
- [ ] Loads list with status filters
- [ ] Create new load → appears in list
- [ ] Assign driver to load → driver visible on load detail

**Owner — Map:**
- [ ] Map loads with vehicle markers (or empty state if no GPS data)
- [ ] Tap vehicle marker → detail sheet
- [ ] Auto-refresh every 60s (verify timestamp in detail sheet)

**Owner — Fleet:**
- [ ] Send message to individual driver → driver receives push + message in app
- [ ] Send broadcast → all active drivers receive push
- [ ] Message history shows sent messages

**Design QA:**
- [ ] Dark mode: all screens look correct
- [ ] Light mode: switch system to light → all screens readable
- [ ] Haptic feedback fires on all documented events
- [ ] No layout overflow on small screen (iPhone SE / small Android)
- [ ] Safe area correct (no content behind notch/Dynamic Island/nav bar)
