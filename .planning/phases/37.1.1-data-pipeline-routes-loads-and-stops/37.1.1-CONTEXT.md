# Phase 37.1.1: Data Pipeline — Routes, Loads, and Stops - Context

**Gathered:** 2026-04-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Fix the broken data pipeline between Routes, Loads, and RouteStops so the driver map has real coordinates to display. This covers: schema changes to link stops to loads, geocoding on load save, auto-creation of RouteStops when a load is assigned to a route, and ensuring the driver map correctly consumes populated stops. Web and mobile both benefit. Does NOT include the invoice changes (Phase 37.1.2) or the owner route-creation UI (Phase 37.2).

</domain>

<decisions>
## Implementation Decisions

### Schema: RouteStop changes
- Add `loadId String? @db.Uuid` — links each stop to the load it serves (nullable: fuel/weigh stops have no load)
- Add `contactName String?` — shipper/receiver contact at this stop
- Add `contactPhone String?`
- Add `bolNumber String?` — Bill of Lading number for this stop's load
- Add `poNumber String?` — Customer PO number

### Schema: Load changes
- Add `pickupStopId String? @db.Uuid` — FK → RouteStop (set when load is assigned to a route)
- Add `deliveryStopId String? @db.Uuid` — FK → RouteStop
- Keep existing `pickupLat/pickupLng/deliveryLat/deliveryLng` — these remain as the geocoding cache on the load itself

### Geocoding trigger
- Geocode origin → pickupLat/pickupLng and destination → deliveryLat/deliveryLng when a Load is created or when origin/destination changes
- Use Google Maps Geocoding API (already in the project for directions)
- Store as Decimal(10,8) / Decimal(11,8) — existing schema types

### RouteStop auto-creation
- When `Load.routeId` is set (load assigned to a route), auto-create two RouteStops:
  - PICKUP stop: address=load.origin, lat=load.pickupLat, lng=load.pickupLng, position=auto, loadId=load.id
  - DELIVERY stop: address=load.destination, lat=load.deliveryLat, lng=load.deliveryLng, position=auto, loadId=load.id
- Then set `load.pickupStopId` and `load.deliveryStopId` back to the created stop IDs
- If a load is removed from a route, delete its associated RouteStops and null out pickupStopId/deliveryStopId

### Stop sequencing for multi-load routes
- Default sequence: all PICKUP stops first (ordered by pickupDate), then all DELIVERY stops (ordered by deliveryDate)
- Position is 1-based integer on RouteStop
- Sequencing runs when a load is added/removed from a route or when stops are reordered

### Driver map behavior
- Map reads `route.stops` ordered by `position` — polyline through all lat/lng coordinates
- Each stop marker shows: address, stop type (PICKUP/DELIVERY), associated load number + BOL number when tapped
- Auto-advance to next stop after driver departs current one (existing geofence logic)
- Stops with null lat/lng are shown in the timeline but skipped in the polyline (graceful degradation)

### Backfill for existing routes
- Existing routes with loads but no RouteStops: run a one-time backfill migration
- For each load with routeId set and pickupLat/deliveryLat available, create RouteStops
- Loads missing coordinates: geocode them as part of the backfill
- Loads with no routeId: leave as-is (no route = no stops to create)

### Claude's Discretion
- Geocoding API call placement (server-side in the load creation/update API route)
- Error handling if geocoding fails (save load without coords, retry async or on next edit)
- Stop position recalculation strategy (full resequence vs append)

</decisions>

<specifics>
## Specific Ideas

- The industry standard model: Route has ordered Stops; each Stop links to a Load; a Load has an explicit pickupStop and deliveryStop. This is how McLeod, TMW, and Aljex work.
- For multi-load routes (LTL), stops are shared: two loads can share a pickup stop at the same address.
- The driver map was broken for ALL existing routes because RouteStops were never written. This phase fixes the entire pipeline, not just test data.

</specifics>

<deferred>
## Deferred Ideas

- Multi-stop loads (one load with intermediate waypoints) — too rare to scope here, handle in future LTL phase
- Manual stop reordering by owner on mobile — Phase 37.2 owner route management
- Shared pickup stops (two loads at same address merged into one stop) — Phase 37.2
- Fuel/weigh station stops (non-load stops) — Phase 37.2

</deferred>
