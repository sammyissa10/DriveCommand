**1. Create `apps/web/src/lib/geo/geocode.ts`:**

Extract the `geocodeAddress` function from `apps/web/src/lib/geofencing/geofence-check.ts` into this new shared module. The function uses **Nominatim (OpenStreetMap)** -- NOT Google Maps (per research, the CONTEXT.md claim about Google Maps is incorrect; the project uses Nominatim everywhere).

```typescript
export async function geocodeAddress(
  address: string
): Promise<{ lat: number; lng: number } | null>
```

- Calls `https://nominatim.openstreetmap.org/search?q=${encoded}&format=json&limit=1`
- Headers: `{ 'User-Agent': 'DriveCommand/1.0 fleet-management' }`
- Timeout: 5000ms via `AbortSignal.timeout(5000)`
- Returns `{ lat, lng }` or `null` on any failure (never throws)
- Parse lat from `data[0].lat`, lng from `data[0].lon` (note: Nominatim uses `lon` not `lng`)

Also export a convenience function for geocoding both ends of a load:
```typescript
export async function geocodeLoadAddresses(
  origin: string,
  destination: string
): Promise<{
  pickupLat: number | null;
  pickupLng: number | null;
  deliveryLat: number | null;
  deliveryLng: number | null;
}>
```
This calls `geocodeAddress` for origin and destination in parallel (`Promise.all`), returning null for any that fail.

**2. Update `apps/web/src/lib/geofencing/geofence-check.ts`:**

Remove the inline `geocodeAddress` function and replace with an import from `@/lib/geo/geocode`. Ensure the existing `checkGeofences` function still works -- it calls `geocodeAddress(stop.address)` and uses the result as `[lat, lng]` tuple. The new shared version returns `{ lat, lng }` object, so update the call site accordingly:

- After: `const coords = await geocodeAddress(stop.address); if (coords) { const { lat, lng } = coords; ... }`

**3. Create `apps/web/src/lib/route-stops/sync-route-stops.ts`:**

Create the RouteStop auto-create/delete/resequence utility with these exported functions:

`createRouteStopsForLoad(tx, params)` — Creates PICKUP and DELIVERY RouteStops for a load being assigned to a route. Params: `{ routeId, tenantId, load: { id, origin, destination, pickupLat, pickupLng, deliveryLat, deliveryLng } }`. Returns `{ pickupStopId, deliveryStopId }`. Must be called inside a Prisma `$transaction`. Uses the `Prisma.TransactionClient` type (import from `@/generated/prisma`). After creating both stops, calls `resequenceRouteStops`.

`deleteRouteStopsForLoad(tx, params)` — Deletes RouteStops for a load being removed from a route. Also nulls out `pickupStopId`/`deliveryStopId` on the Load. Params: `{ routeId, loadId }`. Calls `resequenceRouteStops` after deletion.

`resequenceRouteStops(tx, routeId)` — Full resequence: fetches all stops for the route, sorts PICKUP stops first then DELIVERY stops (within each group, ordered by existing position), assigns 1-based positions.

Key implementation details:
- Use `tx.routeStop.create()` for stop creation (not raw SQL)
- Lat/lng come from the Load's existing `pickupLat/pickupLng/deliveryLat/deliveryLng` fields (Prisma Decimal type). Pass them through as-is to the RouteStop (both use `@db.Decimal(10,8)` / `@db.Decimal(11,8)`)
- Set `status: 'PENDING'` and `geofenceHit: false` on new stops
- After creating stops, update the Load with `pickupStopId` and `deliveryStopId`

**2. Mobile PATCH `/api/mobile/owner/loads/[id]/route.ts`:**

First, expand the PATCH body type to accept the new fields: add `origin?: string`, `destination?: string`, `routeId?: string | null` to the accepted request body schema/type. Also expand the existing load fetch (the `prisma.load.findUnique` or similar at the start of the handler) to `select` the current `origin`, `destination`, and `routeId` values -- these are needed for comparison logic below.

Before the transaction:
- If `origin` or `destination` is present in the request body (address changed), call `geocodeLoadAddresses(newOrigin ?? existingLoad.origin, newDestination ?? existingLoad.destination)` to re-geocode
- If neither changed, skip geocoding

Inside the existing `$transaction`:
- Include geocoded lat/lng in the `tx.load.update()` data (when geocoding was performed)
- Handle `routeId` changes:
  - If `routeId` is being SET (was null, now has value): call `createRouteStopsForLoad` with the new routeId
  - If `routeId` is being CLEARED (was set, now null/removed): call `deleteRouteStopsForLoad` with the old routeId and loadId
  - If `routeId` is CHANGING (different route): delete stops from old route, create stops on new route
  - If address changed AND load has routeId: delete old stops, re-create stops with new coordinates
