## Decisions Made

- Nominatim is the geocoding API (not Google Maps) — the CONTEXT.md had an incorrect claim. Research confirmed Nominatim throughout: `geofence-check.ts`, `autocomplete/route.ts`. Fixed in implementation.
- Geocoding runs **before** `$transaction` — network calls inside DB transactions risk connection pool exhaustion and transaction timeouts. This is the correct architecture.
- RouteStop rebuild on address change: delete existing stops, re-create with new coordinates. Simpler and more consistent than in-place lat/lng updates.
- Web `updateLoad` does an extra `findUnique` before the transaction to get the current `routeId`. This is intentional: the transition logic (set vs. clear vs. change) requires knowing the old value.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Updated geofence-check.ts call sites to use object destructuring**
- **Found during:** Task 1 (refactoring inline function to shared module)
- **Issue:** The old inline `geocodeAddress` returned `[number, number] | null` (tuple). The new shared function returns `{ lat, lng } | null`. Three call sites in `geofence-check.ts` used tuple destructuring `[lat, lng] = coords` which would fail with the new return type.
- **Fix:** Updated all three call sites to `({ lat, lng } = coords)` object destructuring
- **Files modified:** `apps/web/src/lib/geofencing/geofence-check.ts`
- **Committed in:** 2755660 (Task 1)
