    - `delete` (adminProcedure.mutation) — input: `z.object({ id: z.string().uuid() })`. SOFT DELETE: set `isActive: false, deletedAt: new Date()`. Must verify tenantId before updating. Returns `{ success: true }`.

    ```typescript
    const existing = await prisma.stepTemplate.findFirst({
      where: { id: input.id, tenantId: ctx.tenantId, deletedAt: null },

    return prisma.stepTemplate.update({
      where: { id: existing.id },

    });
    ```

    FILE B: `apps/web/src/server/services/workflows/playbookStepService.ts`

    This holds the reorder transaction logic used by the playbook.reorderSteps procedure (kept in a service file because it's more than simple CRUD).

    Function signature:
    ```typescript
    export async function reorderPlaybookSteps(params: {
      playbookId: string;
      tenantId: string;
      steps: Array<{ stepId: string; sequence: number; playbookPhase: PhaseType }>;
    }): Promise<void>
    ```

    Implementation:
    1. Verify the Playbook belongs to this tenant — `findFirst({ where: { id: playbookId, tenantId, deletedAt: null } })`. Throw if not found (`TRPCError code: NOT_FOUND`).
    2. Verify every stepId in `params.steps` belongs to this playbook — `findMany({ where: { playbookId, id: { in: stepIds } } })`. Throw if any mismatch (`TRPCError code: BAD_REQUEST`).
    3. Inside `prisma.$transaction`:
       a. FIRST: set all affected steps to very large temporary sequence values (e.g., `sequence = 10000 + index`) to avoid the unique constraint violation (UNIQUE (playbookId, sequence)) while we're mid-reorder.
       b. THEN: update each step to its final sequence and playbookPhase.
    4. Return void.

    PhaseType import: from `@drivecommand/validation` or from the Prisma client (`@prisma/client` re-export). Prefer the validation package for consistency with Zod types.

    Procedures (9 total):

    `list` (tenantMemberProcedure.query) — input: `z.object({ entityType: playbookEntityTypeSchema.optional() })`.
    - Returns: `findMany({ where: { tenantId: ctx.tenantId, deletedAt: null, ...(input.entityType ? { entityType: input.entityType } : {}) }, orderBy: { createdAt: 'desc' } })`.

    `getById` (tenantMemberProcedure.query) — input: `z.object({ id: z.string().uuid() })`.
    - Returns: Playbook with all steps included: `include: { steps: { include: { stepTemplate: true }, orderBy: [{ playbookPhase: 'asc' }, { sequence: 'asc' }] } }`.
    - Verify tenantId. Throw NOT_FOUND if missing.

    `create` (adminProcedure.mutation) — input: createPlaybookSchema.
    - Creates with `tenantId: ctx.tenantId`.

    `update` (adminProcedure.mutation) — input: updatePlaybookSchema.
    - Tenant-scoped update pattern from Task 1.

    `delete` (adminProcedure.mutation) — input: `z.object({ id: z.string().uuid() })`.
    - Soft delete: set deletedAt + isActive=false.

    `addStep` (adminProcedure.mutation) — input: addStepSchema.
    - Verify the playbook and the stepTemplate both belong to ctx.tenantId.
    - If sequence not provided, compute: `max(sequence) + 1` within this playbookId (use `aggregate` or `findFirst({ orderBy: { sequence: 'desc' } })`).
    - Create the PlaybookStep row.

    `removeStep` (adminProcedure.mutation) — input: removeStepSchema.
    - Verify playbook belongs to tenant, step belongs to playbook.
    - `delete({ where: { id: stepId } })` — hard delete of the junction row (spec allows this; the StepTemplate itself is retained).

    `updateStep` (adminProcedure.mutation) — input: `updatePlaybookStepSchema` (from `@drivecommand/validation`).
    - This is the save path for the builder's StepDetailEditor (Plan 06) — it persists edits to a PlaybookStep's `overrideConfig` and optionally its `playbookPhase`.
    - Implementation:
      1. Verify the Playbook belongs to ctx.tenantId (tenant guard — same pattern as other procedures):
         ```typescript
         const playbook = await prisma.playbook.findFirst({
           where: { id: input.playbookId, tenantId: ctx.tenantId, deletedAt: null },
         });
         if (!playbook) throw new TRPCError({ code: 'NOT_FOUND' });
         ```
      2. Verify the PlaybookStep belongs to that playbook:
         ```typescript
         const step = await prisma.playbookStep.findFirst({
           where: { id: input.stepId, playbookId: input.playbookId },
         });
         if (!step) throw new TRPCError({ code: 'NOT_FOUND' });
         ```
      3. Build the update data object:
         ```typescript
         const data: Prisma.PlaybookStepUpdateInput = {
           overrideConfig: input.overrideConfig,
         };
         if (input.playbookPhase !== undefined) {
           data.playbookPhase = input.playbookPhase;
         }
         ```
      4. Return the updated PlaybookStep (include stepTemplate so the client can re-render without a refetch):
         ```typescript
         return prisma.playbookStep.update({
           where: { id: step.id },
           data,
           include: { stepTemplate: true },
         });
         ```
    - NOTE: Sequence changes go through `reorderSteps`, NOT `updateStep`. `updateStep` is strictly for overrideConfig + phase edits from the StepDetailEditor.

    `reorderSteps` (adminProcedure.mutation) — input: reorderStepsSchema.
    - Delegate to `reorderPlaybookSteps({ playbookId: input.playbookId, tenantId: ctx.tenantId, steps: input.steps })`.
    - Return the updated playbook with steps (same shape as getById).

    Export: `export const playbookRouter = router({ list, getById, create, update, delete: deleteProc, addStep, removeStep, updateStep, reorderSteps })`
