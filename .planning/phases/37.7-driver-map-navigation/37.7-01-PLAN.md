    **VehicleMarker.tsx migration:**
    VehicleMarker.tsx currently imports from react-native-maps (Marker or similar). Rewrite it to use @rnmapbox/maps MarkerView instead. VehicleMarker.tsx has zero importers in actual screens (confirmed by grep — it is only used in the now-removed owner map stub). Preserve the props interface so future phases can use it:

    ```typescript
    import { MarkerView } from '@rnmapbox/maps'

    interface VehicleMarkerProps {
      coordinate: { latitude: number; longitude: number }
      label?: string
      color?: string
    }

    export function VehicleMarker({ coordinate, label, color = '#0ea5e9' }: VehicleMarkerProps) {
      return (
        <MarkerView coordinate={[coordinate.longitude, coordinate.latitude]}>
          {/* Colored circle with optional label */}
          <View style={{ ... }}>
            {label ? <Text style={{ ... }}>{label}</Text> : null}
          </View>
        </MarkerView>
      )
    }
    ```

    Note: Mapbox MarkerView coordinate prop order is [longitude, latitude] (GeoJSON order), opposite of the react-native-maps Marker which used { latitude, longitude } object. Swap accordingly.

    Style the marker as a colored circle (default color #0ea5e9, width/height 32, borderRadius 16) with a small Text label centered inside if label is provided. Use StyleSheet.create for styles — no NativeWind on this component (it renders inside a MapView which has its own rendering context).

    **Driver layout token initialization:**
    At the TOP of apps/mobile/app/(driver)/_layout.tsx, BEFORE the DriverLayout function, add:

    ```typescript
    import Mapbox from '@rnmapbox/maps'
    import Constants from 'expo-constants'

    // Initialize Mapbox token before any MapView renders
    // Token is read from EXPO_PUBLIC_MAPBOX_TOKEN (dev) or app.json extra.mapboxToken (build)
    Mapbox.setAccessToken(
      process.env.EXPO_PUBLIC_MAPBOX_TOKEN ??
      Constants.expoConfig?.extra?.mapboxToken ??
      ''
    )
    ```

    This must be at module level (not inside useEffect or a function) so it runs on import before any child screen attempts to render a MapView.

    **app.json iOS infoPlist:**
    Add LSApplicationQueriesSchemes to the ios.infoPlist section of apps/mobile/app.json:

    ```json
    "ios": {
      "infoPlist": {
        "LSApplicationQueriesSchemes": ["comgooglemaps", "waze", "maps"]
      }
    }
    ```

    If infoPlist already exists in app.json, merge into it. If ios section lacks infoPlist, add it. The "maps" scheme covers Apple Maps canOpenURL checks; "comgooglemaps" covers Google Maps iOS app; "waze" covers Waze.
