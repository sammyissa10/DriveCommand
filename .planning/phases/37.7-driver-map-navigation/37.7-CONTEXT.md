# Phase 37.7: Driver Map + Navigation Screen — Context

**Gathered:** 2026-04-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Add a Map screen to the driver mobile portal showing the driver's live location and their active load route as a drawn polyline. When the driver starts a load, the app auto-redirects to the Map tab and opens Google Maps with the next stop pre-filled for turn-by-turn navigation. This is a hybrid approach: react-native-maps handles the in-app route preview, Google Maps handles the actual navigation.

Restructure driver tab bar to mirror the owner portal pattern (5 tabs + More menu).

</domain>

<decisions>
## Implementation Decisions

### Tab Bar Restructure
- Driver tab bar becomes: **Dashboard · Loads · Map · Messages · More**
- `More` tab contains: HOS, Documents, Incidents, Support Ticket
- This mirrors the owner portal's More-menu pattern exactly
- HOS and Documents move out of the tab bar into More

### Map Screen Placement
- Map is the 3rd tab in the driver tab bar (between Loads and Messages)
- Full-screen MapView using react-native-maps
- showsUserLocation prop enabled for live driver location dot

### Auto-Redirect on Load Start
- When driver taps "Start" on a load (accepts/begins it), two things happen simultaneously:
  1. App navigates to the Map tab
  2. Navigation app opens immediately with the first unvisited stop pre-filled
- One tap does both — driver goes straight into navigation
- Which nav app opens depends on the driver's navigation preference setting (see below)

### Multi-Stop Navigation
- Always navigate to the **next unvisited stop** in sequence (not final destination)
- Same pattern as MapQuest — driver sees current target only
- As stops are marked arrived/departed, "Start Navigation" updates to the new next stop

### Route Polyline
- Fetch route polyline from the existing OSRM proxy (`/api/geocoding/distance`, extended to return full geometry)
- OSRM returns real road polyline — free, no API key, already integrated from quick-147
- Mobile draws polyline on MapView using `react-native-maps` Polyline component
- Markers placed at each stop with sequence number label (1, 2, 3...)
- Active/next stop marker is visually distinct (highlighted color)
- No Google Directions API needed for polyline

### Info Panel (Claude's Discretion)
- Floating bottom sheet style overlay (not a full-screen panel)
- Shows: next stop address, estimated distance, estimated ETA
- "Start Navigation" button is the primary CTA — prominent, bottom of panel
- Claude decides exact layout, card design, and typography

### Map Tab State — No Active Load
- Map tab is always accessible (not hidden when no load)
- Shows full-screen map with driver's live location dot
- No polyline, no stop markers
- "Start Navigation" button is greyed out / disabled
- Small status chip at top: "No active load" 
- Tab icon in tab bar stays normal (not lit up) when no active load

### Map Tab State — Active Load in Progress
- Tab icon stays slightly highlighted/accented to remind driver navigation is available
- Polyline and stop markers drawn on load
- "Start Navigation" button is active (colored, tappable)

### Map Provider (In-App Tiles)
- **Android:** Always Google Maps (`PROVIDER_GOOGLE`) — requires `GOOGLE_MAPS_ANDROID_KEY` in `app.json`
- **iOS default:** Apple Maps (`PROVIDER_DEFAULT`) — free, no key, looks native on iPhone
- **iOS option:** Driver can switch to Google Maps tiles in Settings — requires `GOOGLE_MAPS_IOS_KEY` in `app.json`
- Map provider preference stored in MMKV, persists across sessions
- Setting exposed in driver Settings screen (under a "Map & Navigation" section)

### Navigation App Preference
- Setting in driver Settings screen: which app opens when "Start Navigation" is tapped
- **Android:** Google Maps only (deep-link: `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}`)
- **iOS options:** Apple Maps (default) or Google Maps or Waze
  - Apple Maps: `maps://?daddr={lat},{lng}`
  - Google Maps: `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}`
  - Waze: `waze://?ll={lat},{lng}&navigate=yes`
- Preference stored in MMKV alongside map provider preference
- Falls back to Apple Maps if preferred app is not installed

### API Route (Backend)
- Extend existing OSRM proxy (`/api/geocoding/distance`) to accept multi-stop arrays and return full polyline geometry
- No new Google API needed — OSRM handles the route shape
- Requires mobile Bearer token auth (same `validateMobileToken` pattern)

### api-client Updates
- Add `getDirections(stops: { lat: number; lng: number }[])` method to `driverApi`
- Returns polyline + legs data for map rendering

### Documentation
- Update `apps/mobile/docs/architecture.md` with:
  - New "Navigation Strategy" section explaining hybrid approach rationale
  - Driver tab bar structure (new 5+More layout)
  - API endpoint for directions

### Google API Keys Needed
- `GOOGLE_MAPS_ANDROID_KEY` — Maps SDK for Android (required, renders map tiles on Android)
- `GOOGLE_MAPS_IOS_KEY` — Maps SDK for iOS (only needed if iOS driver switches to Google tiles in settings)
- Both keys go in `apps/mobile/app.json` under `android.config.googleMaps.apiKey` and `ios.config.googleMapsApiKey`
- No Google Directions API needed (OSRM handles polyline)

### Claude's Discretion
- Exact info panel component design and spacing
- Tab icon choice for Map tab (likely a map-pin or navigation icon from lucide)
- Polyline color and thickness
- Stop marker appearance beyond "numbered + highlighted active stop"
- Loading skeleton/spinner while polyline fetches
- Exact Settings UI layout for map/navigation preferences

</decisions>

<specifics>
## Specific Ideas

- "When you start the batch it should automatically redirect you to the maps tab with the navigation already started" — one-tap start load = map tab + Google Maps open simultaneously
- Multi-stop behavior should work like MapQuest: only shows current/next stop target, not all stops at once in Google Maps
- Tab icon should stay "lit" in some way when there's an active load and the driver is in navigation mode
- **Mimic Samsara / KeepTruckin (Motive) navigation UX:** These apps show a full-screen in-app map with the route drawn, current location dot, stop markers, and an ETA panel — then deep-link to Google Maps for actual turn-by-turn. This is exactly the hybrid approach we're building.

</specifics>

<deferred>
## Deferred Ideas

- **Full in-app turn-by-turn navigation (Waze/Google Maps level)** — Step-by-step maneuver instructions, voice guidance, auto-rerouting, traffic data, all inside DriveCommand. This is a future milestone (6-8 phases). Defer until hybrid ships and driver feedback confirms the need.

</deferred>
