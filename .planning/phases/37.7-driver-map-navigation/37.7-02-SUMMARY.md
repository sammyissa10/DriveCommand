# Phase 37.7 Plan 02: Directions Backend Summary

**OSRM multi-stop directions proxy at POST /api/geocoding/directions returning GeoJSON polyline, with RouteStop lat/lng and driverApi.getDirections added to api-client**

## Performance

## Accomplishments

- Extended osrm.ts with `getOSRMDirections` supporting multi-stop routes via `overview=full&geometries=geojson`, returning `[lng, lat]` polyline matching GeoJSON/Mapbox convention
- Created POST /api/geocoding/directions endpoint with full validation, rate limiting (`dir:` prefix), and graceful null response on OSRM unavailability
- Updated RouteStop interface with `lat: number | null` and `lng: number | null` fields; added `DirectionsResult` type and `driverApi.getDirections` method to api-client

## Task Commits

1. **Task 1: Add getOSRMDirections to osrm.ts** - `0f2a692` (feat)

## Files Created/Modified

- `apps/web/src/lib/geo/osrm.ts` — Added `OSRMDirectionsResult` interface and `getOSRMDirections` function
- `apps/web/src/app/api/geocoding/directions/route.ts` — New POST endpoint proxying OSRM multi-stop directions
- `packages/api-client/src/driver.ts` — Added `lat`/`lng` to `RouteStop`, added `DirectionsResult` type and `driverApi.getDirections` method

## Decisions Made

- Return 200 with `{ polyline: null, distanceMiles: null, durationSeconds: null }` when OSRM returns null — allows mobile map to render without a route polyline without crashing
- Rate limit key uses `dir:` prefix (not `dist:`) to keep directions and distance quotas independent on the shared `geocodingLimiter`
- Polyline coordinates remain in GeoJSON `[lng, lat]` order end-to-end — no coordinate swapping needed on the mobile side when feeding into Mapbox ShapeSource
