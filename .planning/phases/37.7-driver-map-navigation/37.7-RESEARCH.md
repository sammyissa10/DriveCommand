## Summary

This phase adds a driver Map screen and restructures the driver tab bar from the current 5-tab layout (Loads, HOS, Home, Messages, Documents) to the new 5+More pattern (Dashboard, Loads, Map, Messages, More). The Map screen displays the driver's live location via Mapbox and draws an OSRM polyline for the active load route. When a driver starts a load, the app simultaneously navigates to the Map tab and deep-links into the driver's preferred navigation app.

The key technical challenge is that `@rnmapbox/maps` is NOT currently installed — it appears only as a placeholder in `app.json` and `.env.example`. The project currently has `react-native-maps@1.27.2` installed (referenced only in `VehicleMarker.tsx`, which is not imported anywhere in actual screens). Phase 37.7 must install `@rnmapbox/maps`, remove the `react-native-maps` dependency from mobile's `package.json` (it is unused in driver screens), and trigger a fresh dev build.

The OSRM proxy (`/api/geocoding/distance`) currently accepts two points and returns only distance. It must be extended to a new endpoint that accepts N stops and returns the full GeoJSON polyline geometry.

**Primary recommendation:** Install `@rnmapbox/maps` via `expo install`, add `Mapbox.setAccessToken` call in the app entry point reading from `expo-constants`, then implement MapView + ShapeSource/LineLayer + UserLocation in the driver map screen. Extend OSRM proxy to `/api/geocoding/directions` (new route, not modifying the existing distance route). Use `router.navigate('/(driver)/map')` for tab switching.

### Pattern 1: Mapbox MapView with UserLocation and Polyline
**What:** Full-screen MapView with live user location dot and GeoJSON LineString polyline drawn via ShapeSource/LineLayer.
**When to use:** Whenever rendering the driver map screen.

```typescript

  MapView,
  Camera,
  UserLocation,
  ShapeSource,
  LineLayer,

  type: 'Feature',
  geometry: {
    type: 'LineString',
```

### Pattern 2: OSRM Multi-Stop Directions API
**What:** New Next.js API route that accepts an array of stops and returns GeoJSON polyline geometry.
**When to use:** Called from `getDirections` in `driverApi`.

```typescript
// Source: https://project-osrm.org/docs/v5.5.1/api/
// OSRM URL format: /route/v1/driving/{lng1,lat1;lng2,lat2;lng3,lat3}
//                  ?overview=full&geometries=geojson
// Response: routes[0].geometry = { type: 'LineString', coordinates: [[lng, lat], ...] }
// Note: OSRM coordinate order is lng,lat — same as current osrm.ts utility

const coordsStr = stops.map(s => `${s.lng},${s.lat}`).join(';')
const url = `http://router.project-osrm.org/route/v1/driving/${coordsStr}?overview=full&geometries=geojson`
```

Response shape:
```json
{
  "code": "Ok",
  "routes": [{
    "distance": 12345.6,
    "duration": 890.2,
    "geometry": {
      "type": "LineString",
      "coordinates": [[-87.629, 41.878], [-87.631, 41.880], ...]
    }
  }]
}
```

### Pattern 3: Auto-Redirect + Navigation Deep Link (One Tap)
**What:** When driver taps "Start" on a load, simultaneously navigate to the Map tab and open the external navigation app.
**When to use:** `StatusUpdateButton` or wherever "Start Load" is triggered.

```typescript
// Source: https://docs.expo.dev/versions/latest/sdk/router/
//         https://docs.expo.dev/linking/into-other-apps/
import { useRouter } from 'expo-router'
import * as Linking from 'expo-linking'
import { kvStorage } from '../../lib/storage'

const router = useRouter()

async function handleStartLoad(nextStop: { lat: number; lng: number }) {
  // 1. Switch to Map tab
  router.navigate('/(driver)/map')

  // 2. Open navigation app with next stop
  const navPref = kvStorage.getString('nav_app_preference') ?? 'apple'
  const url = buildNavUrl(navPref, nextStop.lat, nextStop.lng)
  await Linking.openURL(url)
}

function buildNavUrl(pref: string, lat: number, lng: number): string {
  switch (pref) {
    case 'google':
      return `https://www.google.com/maps/dir/?api=1&destination=${lat},${lng}&travelmode=driving`
    case 'waze':
      return `waze://?ll=${lat},${lng}&navigate=yes`
    case 'apple':
    default:
      return `maps://?daddr=${lat},${lng}`
  }
}
```

### Anti-Patterns to Avoid
- **Calling `Mapbox.setAccessToken` inside a component render:** Call it at module level in `_layout.tsx` or `map.tsx`, not inside a `useEffect` that might miss the first render.
- **Using `overview=simplified` for the polyline:** Always use `overview=full` — simplified drops points at lower zoom levels and makes the polyline visually jump as the driver zooms in.
- **Passing `url` prop to `ShapeSource` for the polyline:** A documented 2025 bug shows URL-sourced ShapeSource layers may not render. Use the `shape` prop directly with the GeoJSON object.
- **Storing Mapbox token in `.env` only:** Token must also be in `app.json` `extra.mapboxToken` so it is bundled into the app for runtime access via `expo-constants`.
- **Using `router.push` instead of `router.navigate` for tab switching:** `push` creates a new stack entry; `navigate` uses the existing tab and is idempotent (correct for tab switching).
- **Querying iOS URL scheme availability without `LSApplicationQueriesSchemes`:** `Linking.canOpenURL('comgooglemaps://')` always returns false on iOS unless the scheme is listed in `app.json` `ios.infoPlist.LSApplicationQueriesSchemes`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Map rendering | Custom WebView + Leaflet | `@rnmapbox/maps` MapView | Native SDK, proper touch handling, camera animation |
| Polyline geometry | Haversine line between two points | OSRM `overview=full&geometries=geojson` | Real road shape, free, already proxied |
| User location dot | Manual `expo-location` watch + custom View overlay | `@rnmapbox/maps` UserLocation component | Handles heading, platform differences, pulsing natively |
| Navigation app detection | Hardcoded OS check + manual URL building | `Linking.canOpenURL` + fallback chain | User may not have Waze installed; must check before opening |
| Tab switching | `useNavigation().dispatch(TabActions.jumpTo)` | `router.navigate('/(driver)/map')` | Expo Router's idiomatic imperative tab switch |
| Preferences storage | AsyncStorage | `kvStorage` (MMKV) | Already the project standard; synchronous, fast |

**Key insight:** The OSRM public API gives everything needed for a real road polyline without any API key. The only cost is a 5s timeout risk on slow networks — use AbortController (same pattern as existing `osrm.ts`).

## Common Pitfalls

### Pitfall 1: @rnmapbox/maps Not Installed (Critical — Current State)
**What goes wrong:** `app.json` has the plugin placeholder and `MAPBOX_ACCESS_TOKEN` appears in `.env.example`, but `@rnmapbox/maps` is not in `package.json` and not installed in `node_modules`.
**Why it happens:** quick-147 set up the placeholder config but never installed the package.
**How to avoid:** Run `npx expo install @rnmapbox/maps` from `apps/mobile` before writing any map screen code. Then rebuild the dev client (the existing dev build will crash without the native module).
**Warning signs:** "Unable to resolve module @rnmapbox/maps" at Metro startup.

### Pitfall 2: Dev Build Required After Installing @rnmapbox/maps
**What goes wrong:** Developers run Expo Go or the existing dev build without rebuilding — app crashes immediately because native modules are missing.
**Why it happens:** @rnmapbox/maps requires native code linking. Expo Go is explicitly incompatible.
**How to avoid:** After `expo install @rnmapbox/maps`, run `eas build --profile development --platform android` (or local prebuild for quick iteration). Per project preference: Android emulator only, never Expo Go.
**Warning signs:** "No native module found for RNMBXMapView" or similar RN red screen.

### Pitfall 3: OSRM Coordinate Order (lng, lat — Not lat, lng)
**What goes wrong:** Stops passed in lat/lng order produce routes in the wrong part of the world or "No route found."
**Why it happens:** OSRM uses GeoJSON convention (lng, lat) while the rest of the app uses (lat, lng). The existing `osrm.ts` already handles this correctly for 2-point routes.
**How to avoid:** The new directions endpoint must swap coords: `${stop.lng},${stop.lat}` in the URL. In the GeoJSON response, `coordinates` are also `[lng, lat]` — Mapbox ShapeSource expects this order natively (GeoJSON standard), so no swap needed on the frontend.
**Warning signs:** Route polyline appears in ocean or wrong country.

### Pitfall 4: iOS Navigation App Queries Require infoPlist
**What goes wrong:** `Linking.canOpenURL('comgooglemaps://')` and `Linking.canOpenURL('waze://')` return false on iOS even when apps are installed.
**Why it happens:** iOS 9+ requires explicit scheme declarations in `LSApplicationQueriesSchemes`.
**How to avoid:** Add to `app.json` `ios.infoPlist`:
```json
"LSApplicationQueriesSchemes": ["comgooglemaps", "waze", "maps"]
```
**Warning signs:** Fallback to Apple Maps even when user has Google Maps installed.

### Pitfall 5: Mapbox Access Token Not Bundled
**What goes wrong:** `Constants.expoConfig?.extra?.mapboxToken` returns `undefined` in production builds, causing the map to show a blank tile or "Invalid token" error.
**Why it happens:** `.env` values are not automatically bundled into the app binary. Only values in `app.json` `extra` are available via `expo-constants`.
**How to avoid:** The token placeholder is already in `app.json` as `"mapboxToken": "MAPBOX_PUBLIC_TOKEN_PLACEHOLDER"`. Before a real build, replace this value (or use EAS Secrets with `app.config.js`). For dev builds, set `EXPO_PUBLIC_MAPBOX_TOKEN` in `.env` and read it via `process.env.EXPO_PUBLIC_MAPBOX_TOKEN`.
**Warning signs:** Blank map tiles, "Not Authorized" Mapbox error in Metro logs.

### Pitfall 6: Tab Bar Has Exactly 5 Visible Tabs (Current: Also 5, Different Order)
**What goes wrong:** Adding a new tab while preserving hidden screens causes the tab bar to show 6 items.
**Why it happens:** Each `<Tabs.Screen>` with a visible `href` appears in the tab bar. The `incidents` screen is already hidden with `href: null`. The new `more` and `map` screens add 2 visible items; HOS and Documents must be hidden.
**How to avoid:** In the new `_layout.tsx`, set `href: null` on `hos`, `documents`, and `incidents`. Only `index`, `loads`, `map`, `messages`, and `more` should be visible.
**Warning signs:** Tab bar overflows or shows 6+ items.

### Pitfall 7: Stop Coordinate Data Not Available on Loads Endpoint
**What goes wrong:** The `LoadDetail.stops` array (from `driverApi.getLoad`) has `address` as a string but no `lat`/`lng` fields — so you cannot directly pass stops to the OSRM directions endpoint.
**Why it happens:** The existing `RouteStop` type (in `driver.ts`) has `address: string` but no coordinates.
**How to avoid:** Two options: (A) geocode stop addresses on the backend when returning directions, or (B) add `lat`/`lng` fields to `RouteStop` from the DB. Check whether `stops` in the DB already have coordinate columns. If not, the directions API will need to geocode addresses. This needs investigation during planning — it affects the API design significantly.
**Warning signs:** The `getDirections` API call has nothing to pass as coordinates.

## State of the Art

| Old Approach | Current Approach | Impact |
|--------------|------------------|--------|
| `react-native-maps` (Google-centric, separate iOS/Android keys) | `@rnmapbox/maps` (single token, Mapbox SDK v11) | One token, no Google Cloud account required |
| Haversine straight-line distance | OSRM real road routing | Accurate polyline, actual miles |
| `overview=false` (distance only) | `overview=full&geometries=geojson` | Full road-following polyline returned |
| `Tabs.Screen href={null}` for hidden screens | Still the standard in expo-router v3+ | No change in pattern |
| `router.push` for all navigation | `router.navigate` for tab switching | Avoids duplicate stack entries |

**Current state: @rnmapbox/maps defaults to Mapbox Maps SDK v11** (as of v10.2+). This is the correct version to use — v10 is deprecated. The package name stays `@rnmapbox/maps` regardless.

**Deprecated / outdated:**
- `react-native-mapbox-gl` (old package name): Replaced by `@rnmapbox/maps`
- `@react-native-mapbox-gl/maps`: Also replaced by `@rnmapbox/maps`
- `overview=simplified`: Produces jagged polylines at close zoom — use `full`

## Open Questions

1. **Do load stops have coordinates stored in the database?**
   - What we know: `RouteStop` type has `address: string` but no `lat`/`lng` fields in the current API client types
   - What's unclear: Whether the DB `stops` table has coordinate columns that are simply not exposed in the API response, or whether stops are address-only and would need geocoding
   - Recommendation: Before writing the directions API, run `SELECT column_name FROM information_schema.columns WHERE table_name = 'stops'` against the Supabase DB to check. If coordinates exist, add them to the `RouteStop` type and API response. If not, the directions endpoint must geocode addresses first (adds latency and complexity).

2. **Does `VehicleMarker.tsx` need to be migrated to Mapbox before removing `react-native-maps`?**
   - What we know: `VehicleMarker.tsx` imports from `react-native-maps` but is not imported anywhere in actual screens (grep confirms zero importers). The owner map screen (`(owner)/map.tsx`) is a stub showing "Google Maps API key required."
   - What's unclear: Whether a future phase plans to implement the owner live map with Mapbox (which would need `VehicleMarker` migrated)
   - Recommendation: Remove `react-native-maps` from `apps/mobile/package.json` and update `VehicleMarker.tsx` to use `@rnmapbox/maps` MarkerView instead (simple change). This is within scope since VehicleMarker has no active importers.

3. **Should `Mapbox.setAccessToken` be called once in `_layout.tsx` or in `map.tsx`?**
   - What we know: Official docs recommend calling it before any MapView renders; module-level calls run immediately on import.
   - What's unclear: Whether calling it in `(driver)/_layout.tsx` (which is always mounted) vs `map.tsx` (only mounted on tab visit) matters.
   - Recommendation: Call it in `(driver)/_layout.tsx` at module level (same file where the tab bar is configured). This guarantees it runs before any child screen mounts, even if the user navigates directly to the Map tab.
