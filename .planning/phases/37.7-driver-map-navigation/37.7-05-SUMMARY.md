# Phase 37.7 Plan 05: Start Route Navigation Deep Link + Nav Settings Summary

One-tap "Start Route" simultaneously switches the driver to the Map tab and opens their preferred navigation app via a deep link, backed by a new MMKV-persisted preference screen.

## What Was Built

### lib/navigation.ts
New utility module with four exports:
- `getNavPreference()` — reads MMKV key `nav_app_preference`; Android always returns `'google'`; iOS defaults to `'apple'`
- `setNavPreference(pref)` — writes to MMKV synchronously via kvStorage
- `buildNavUrl(pref, lat, lng)` — constructs the correct deep link URL per app (maps://, waze://, https://maps.google.com)
- `openNavigation(lat, lng)` — opens the preferred app, falls back Waze -> Apple Maps if Waze not installed; never throws

### StatusUpdateButton.tsx
After a successful EN_ROUTE status update (and query invalidation):
1. `router.navigate('/(driver)/map')` — tab switch (does not push stack)
2. `openNavigation(lat, lng)` — deep links to navigation app for next unvisited stop (fire-and-forget)

### map.tsx
The "Start Navigation" Pressable's `onPress` now calls `openNavigation(lat, lng)` for the next unvisited stop. The disabled state from Plan 04 is preserved.

### more/nav-settings.tsx
Platform-conditional navigation preference screen:
- iOS: 3-option picker (Apple Maps / Google Maps / Waze) with check mark on selected; saves immediately via setNavPreference
- Android: static info card — "Google Maps is used for navigation on Android"
- Reachable via More -> Navigation App (already wired in driver More index from a prior plan)
