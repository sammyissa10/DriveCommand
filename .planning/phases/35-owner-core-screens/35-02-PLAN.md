### 2. Build owner loads list screen
File: apps/mobile/app/(owner)/loads.tsx

- Horizontal scrollable status tabs (All, Active, Pending, Delivered)
- FlashList with owner LoadCard component
- Owner load card includes: load number, customer name, origin→destination, driver name (or "Unassigned" in amber), status badge, rate ($X,XXX)
- FAB (+) → create load bottom sheet
- Pull-to-refresh

### 3. Build create load bottom sheet
File: apps/mobile/components/owner/CreateLoadSheet.tsx

Fields (in order):
1. Customer (searchable list from GET /api/mobile/owner/customers — returns customer names)
2. Origin (TextInput)
3. Destination (TextInput)
4. Pickup Date (DateTimePicker, optional)
5. Rate (TextInput, keyboardType numeric, with $ prefix display)
6. Assign Driver (optional select from active driver list)

Validation: Origin and Destination required. Submit creates load.

### 6. Build owner load detail screen
File: apps/mobile/app/(owner)/loads/[id].tsx

Sections:
- Load info (same as driver view)
- Stop timeline (same as driver view)
- Actions section (owner-only):
  - Assign Driver: select → PATCH load with driverId
  - Change Status: select next valid status → confirmation sheet
  - Cancel Load: destructive confirmation → PATCH status=CANCELLED

Owner can transition to any status (more permissive than driver).
