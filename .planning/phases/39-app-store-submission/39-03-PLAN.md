# Phase 39 — Plan 03: Submission, Review, and Launch

## Goal
Submit both apps to their respective stores, handle any review rejection, and execute the launch rollout.

## Prerequisites
- Plans 39-01 and 39-02 complete (all assets and listings ready)
- Production builds exist from Phase 38-01

## Tasks

### 1. Submit iOS to App Store Review
```bash
cd apps/mobile

# If using latest production build from EAS:
eas submit --platform ios --profile production --latest

# This uploads the .ipa to App Store Connect and submits for review
# Monitor at: App Store Connect → TestFlight (internal) → then App Store tab
```

In App Store Connect, after upload:
1. Go to App Store tab (not TestFlight)
2. Select the build in the Version section
3. Verify all metadata is complete
4. Click "Submit for Review"
5. Answer compliance questions (export encryption: no if using only HTTPS)

Review timeline: 1-7 days (average 2-3 for first submission).

### 2. Submit Android to Google Play Review
```bash
eas submit --platform android --profile production --latest
# Submits .aab to Internal Testing track first
```

In Play Console:
1. Verify Internal Testing build is live (test on your Android device)
2. Promote to Production: Releases → Production → Create Release
3. Select the build
4. Add release notes: "Initial release of DriveCommand for Android"
5. Set rollout: 10% initially
6. Submit for Review

Review timeline: 1-3 days (faster for subsequent releases).

### 3. Rejection response playbook
Common rejection reasons and fixes:

**Apple: 2.1 — Performance: App Completeness**
- Cause: App crashes or freezes during review
- Fix: Test with the demo account specifically, ensure no crashes on fresh install

**Apple: 5.1.1 — Location Services**
- Cause: Background location not sufficiently justified
- Fix: Update review notes to explain the fleet management use case more clearly
- Never request background location without it being actively used

**Apple: 4.0 — Design**
- Cause: App looks like a web wrapper
- Fix: Ensure native UI patterns are used (our NativeWind setup should pass)

**Apple: Demo account doesn't work**
- Fix: Verify demo account credentials before submitting, test on a real device

**Google: Policy violation — Location in background**
- Fix: Complete the Location Permissions Declaration form in Play Console
- Declare: delivery tracking is a core feature requiring background location

**Google: Target API level**
- Fix: EAS automatically targets the latest required API level

### 4. Monitor review status
iOS: App Store Connect → Activity → App Review
Android: Play Console → Inbox → notifications

Set up alerts:
- App Store Connect sends email on status change
- Play Console sends email on status change

### 5. Rotate production credentials (pre-launch security)

Before going live, rotate all secrets that existed in plaintext on the dev machine during development. Each service issues a new key; the old one is revoked.

1. **Anthropic API key** — console.anthropic.com → API Keys → delete old → create new → update `ANTHROPIC_API_KEY` in Vercel env vars
2. **Supabase DB password** — Supabase project → Settings → Database → Reset database password → update `DATABASE_URL` and `DIRECT_URL` in Vercel env vars
3. **Gmail app password** — myaccount.google.com → Security → 2-Step Verification → App passwords → delete old → create new → update `EMAIL_PASSWORD` in Vercel env vars
4. **Resend API key** — resend.com → API Keys → delete old → create new → update `RESEND_API_KEY` in Vercel env vars
5. **Vercel deploy hook** — Vercel → Project → Settings → Git → Deploy Hooks → delete old → create new → update local `.env.local`

After updating each key in Vercel:
```bash
vercel env pull  # verify the new values pulled correctly
vercel --prod    # redeploy with new credentials
```

Verify the app still functions end-to-end after the credential rotation before proceeding to store submission.

### 6. Post-approval launch steps

**iOS launch:**
1. App Store Connect → set Release Date (or "Release as soon as approved")
2. 100% rollout (iOS doesn't support phased rollout for new apps)
3. App goes live typically within hours of approval

**Android launch:**
1. Play Console → Production → Promote to 10% rollout
2. Monitor crash rate and ANR rate in Android Vitals for 24 hours
3. If stable: 50% rollout
4. After another 24 hours: 100% rollout

### 6. Post-launch monitoring
Immediately after launch:
- Monitor Expo crash reports (expo.dev dashboard)
- Monitor Vercel function logs for mobile API endpoint errors
- Check Play Console → Android Vitals for crash rate (should be < 1%)
- Verify push notifications still working (send a test message from owner portal)
- Verify OTA updates work (push a small JS change, verify it appears within 5 min)
