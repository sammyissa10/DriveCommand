# Phase 37.1: Driver Portal Gaps - Context

**Gathered:** 2026-03-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Close two remaining gaps in the driver mobile portal:
1. **My Route screen** — driver's currently assigned route with loads linked to that route (multi-stop timeline), route + truck details, and route status context
2. **Driver support ticket FAB** — a persistent floating action button on all driver screens that opens a submit-only support ticket form (no file upload, no ticket history)

Creating/editing routes and viewing ticket history are separate concerns and out of scope.

</domain>

<decisions>
## Implementation Decisions

### My Route — Navigation placement
- Lives inside the **Loads tab** as a pinned card at the top of the screen
- Card is **hidden entirely** when no route is assigned — loads list is unchanged
- Tapping the card **pushes a new full-screen route detail screen** (does not expand inline)
- Screen header matches the web app: title **"My Route"** + subtitle `{origin} → {destination}`

### My Route — Screen sections (mobile)
- **Loads on this route** — vertical timeline of linked loads (see timeline decisions below)
- **Route + truck details** — scheduled date, status badge, truck make/model/VIN/plate
- **Route messages** — route-scoped messaging thread (matches existing Messages tab pattern)
- Route documents and truck documents are **omitted on mobile** — drivers access docs via the Docs tab
- Completed route history is **omitted** — simplifies the mobile screen; history is on the web

### My Route — Route status
- Route status badge shown **prominently in the header area**, next to the title
- Uses existing `Badge` component with appropriate variant (e.g., info for active, success for completed)

### My Route — Stop timeline
- Loads on the route are displayed as a **vertical timeline** with connector lines and circle node markers
- Completed/delivered stops have **filled/colored nodes**; upcoming stops have muted nodes
- Each stop shows: **load number + origin → destination + status badge** (matching web card style)
- The timeline is **read-only** — tapping a stop navigates to the existing load detail screen `/(driver)/loads/[id]` where status updates happen
- This avoids duplicating status-update logic and keeps the route screen as a context view

### My Route — Dashboard integration
- Whether the Dashboard active load card shows a "View Route" shortcut is **Claude's discretion** — add it if the route is assigned and it doesn't crowd the card

### Support tickets — FAB placement
- **Persistent FAB** (LifeBuoy icon, bottom-right) present on **all authenticated mobile screens** — both driver and owner portals
- FAB is implemented in the **driver `_layout.tsx` and owner `_layout.tsx`** so it overlays every tab screen without per-screen wiring
- FAB position: `bottom: 88` (above the tab bar at 72px height + breathing room) on both portals

### Support tickets — Form
- Opens as a **bottom sheet** (using the existing `BottomSheet` component) — matches native mobile patterns
- Fields: **category** (Billing / Bug Report / Feature Request / General), **priority** (Low / Normal / High / Urgent), **title** (required, min 3 chars), **description** (required, min 10 chars, max 2000)
- **No file attachment** — excluded per user decision
- Platform field: **auto-set to MOBILE and hidden** — always mobile in the app context
- `fromPage` is populated from the current route screen name (Expo Router `usePathname` equivalent)

### Support tickets — Submission behavior
- On success: **toast notification** ("Ticket #XXXX submitted! We'll be in touch soon.") + bottom sheet closes + form resets
- Matches web behavior; no separate success screen needed — toast is sufficient for mobile

### Claude's Discretion
- Whether to show a "View Route" shortcut on the Dashboard active load card
- Exact connector line styling for the timeline (color, thickness, dashed vs solid)
- Loading skeleton design for the My Route screen
- Error state handling for route and ticket API calls
- Exact bottom sheet snap points / height for the support ticket form

</decisions>

<specifics>
## Specific Ideas

- Web My Route page structure (`apps/web/src/app/(driver)/my-route/page.tsx`) is the reference for sections and data: loads list, route/truck details, route messages
- Web support ticket modal (`apps/web/src/components/support/support-ticket-modal.tsx`) is the reference for form fields, categories, priorities, and FAB positioning pattern
- Web FAB uses `fixed bottom-20 lg:bottom-6 right-6` — mobile equivalent should clear the tab bar
- Driver loads detail screen (`/(driver)/loads/[id]`) already exists and handles status updates — route timeline taps into it

</specifics>

<deferred>
## Deferred Ideas

- Ticket history/list view for drivers — submit-only for now; history is a future addition
- Truck documents and completed route history on mobile — available on web, deferred from mobile scope
- Route status update from mobile — drivers update load status via load detail, not route screen

</deferred>
