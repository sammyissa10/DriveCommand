# Phase 37.1 Plan 01: My Route Backend + RouteCard Summary

**GET /api/mobile/driver/route endpoint, route-thread messages API, DriverRoute types, RouteCard pinned header, and RouteLoadTimelineItem — the data layer and entry point for the My Route feature**

## Accomplishments
- Built `GET /api/mobile/driver/route` returning active route with loads + truck data, or `{ route: null }` when unassigned
- Built `GET/POST /api/mobile/driver/messages/route-thread` for route-scoped messaging with ownership verification
- Added `DriverRoute`, `DriverRouteLoad`, `DriverRouteTruck` types and `getMyRoute`, `getRouteMessages`, `sendRouteMessage` to driverApi
- Created `RouteCard` pinned header component showing route status, origin/destination, scheduled date, truck info
- Created `RouteLoadTimelineItem` timeline component (ready for plan-02 detail screen)
- Wired `RouteCard` into Loads tab via memoized `ListHeaderComponent` — card shows when route assigned, hidden otherwise

- `apps/web/src/app/api/mobile/driver/messages/route-thread/route.ts` - GET/POST route-scoped messages with ownership check
- `packages/api-client/src/driver.ts` - DriverRoute/DriverRouteLoad/DriverRouteTruck types, getMyRoute/getRouteMessages/sendRouteMessage

## Decisions Made
- Route endpoint returns `{ route: null }` with 200 (not 404) when no active route assigned — consistent with the dashboard pattern and prevents error states in the mobile client
- `route-thread` is a completely separate endpoint from the general messages endpoint — scoped exclusively to `routeId`, not `loadId`, to avoid conflating load and route message threads
- `RouteCard` only appears in the active tab; when no route is assigned the `listHeader` is null so the loads list is unchanged
