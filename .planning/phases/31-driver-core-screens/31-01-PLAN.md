  <name>Task 1: Create Bearer token validator utility</name>
  <files>apps/web/src/lib/auth/mobile-auth.ts</files>
  <action>
Create a reusable function `validateMobileToken(req: Request)` that:
1. Reads the `Authorization: Bearer <token>` header from the request
2. Verifies the JWT using the same secret/method as the existing session auth (reference /api/auth/me for the pattern)
3. Returns `{ userId: string, tenantId: string, role: UserRole, driverId?: string }` on success
4. Returns `null` on failure (caller handles 401 response)

Also export a helper `unauthorizedResponse()` that returns `NextResponse.json({ error: 'Unauthorized' }, { status: 401 })` to reduce boilerplate in route handlers.

If the user's role is DRIVER, look up the Driver record by userId to include driverId in the return value. This is needed by all driver endpoints.
  </action>
  <verify>TypeScript compiles without errors: `cd apps/web && npx tsc --noEmit`</verify>
  <done>validateMobileToken extracts Bearer token, verifies JWT, returns user context with driverId for DRIVER role users, returns null for invalid tokens</done>
</task>

<task type="auto">
  <name>Task 2: Create dashboard and loads list REST endpoints</name>
  <files>
    apps/web/src/app/api/mobile/driver/dashboard/route.ts
    apps/web/src/app/api/mobile/driver/loads/route.ts
  </files>
  <action>
**GET /api/mobile/driver/dashboard/route.ts:**
- Call validateMobileToken, return 401 if null
- Query: find first load where driverId matches and status IN [PENDING, ACCEPTED, EN_ROUTE] — this is the activeLoad
- Query: count RouteStops with status DEPARTED for this driver today — stopsCompleted
- todayMiles: hardcode 0 for now (no GPS data source yet)
- hosHoursRemaining: hardcode 11.0 for now (no HOS tracking yet)
- recentAlerts: query last 5 alerts/notifications for this driver (or return empty array if no alerts table exists)
- Return JSON: `{ activeLoad, todayMiles, stopsCompleted, hosHoursRemaining, recentAlerts }`

**GET /api/mobile/driver/loads/route.ts:**
- Call validateMobileToken, return 401 if null
- Read `?status=active|history` query param (default: active)
- active: query loads where driverId matches AND status IN [PENDING, ACCEPTED, EN_ROUTE]
- history: query loads where driverId matches AND status IN [DELIVERED, INVOICED, CANCELLED]
- Include customer name in each load (Prisma include)
- Sort by updatedAt desc
- Return JSON array of loads
  </action>
  <verify>
Start dev server, use curl to test:
- `curl -H "Authorization: Bearer <valid_token>" http://localhost:3000/api/mobile/driver/dashboard` returns 200 with expected shape
- `curl -H "Authorization: Bearer <valid_token>" http://localhost:3000/api/mobile/driver/loads?status=active` returns 200 with array
- `curl http://localhost:3000/api/mobile/driver/dashboard` (no auth) returns 401
  </verify>
  <done>Dashboard endpoint returns driver's active load + stats. Loads endpoint returns filtered loads by status. Both reject unauthenticated requests with 401.</done>
</task>

<task type="auto">
  <name>Task 3: Create load detail and status update REST endpoints</name>
  <files>
    apps/web/src/app/api/mobile/driver/loads/[id]/route.ts
    apps/web/src/app/api/mobile/driver/loads/[id]/status/route.ts
  </files>
  <action>
**GET /api/mobile/driver/loads/[id]/route.ts:**
- Call validateMobileToken, return 401 if null
- Query load by ID with Prisma includes: stops (RouteStop[] ordered by sequence ASC), truck (id, name, licensePlate, make, model), customer (id, name, email, phone)
- Security check: verify load.driverId === authenticated driverId, return 403 if mismatch
- Return 404 if load not found
- Return full load object with nested stops, truck, customer

**POST /api/mobile/driver/loads/[id]/status/route.ts:**
- Call validateMobileToken, return 401 if null
- Parse body: `{ status: LoadStatus }`
- Fetch load by ID, verify load.driverId === driverId (403 if mismatch)
- Validate status transition:
  - PENDING -> ACCEPTED (only valid next)
  - ACCEPTED -> EN_ROUTE (only valid next)
  - EN_ROUTE -> DELIVERED (only valid next)
  - Any other transition -> 400 with `{ error: 'Invalid status transition' }`
- Update load status in DB
- Return `{ success: true, load: updatedLoad }`
  </action>
  <verify>
Test with curl:
- `curl -H "Authorization: Bearer <token>" http://localhost:3000/api/mobile/driver/loads/<id>` returns load with stops, truck, customer
- `curl -X POST -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -d '{"status":"ACCEPTED"}' http://localhost:3000/api/mobile/driver/loads/<id>/status` returns success
- Attempting an invalid transition (e.g., PENDING -> DELIVERED) returns 400
  </verify>
  <done>Load detail returns full load with stops/truck/customer. Status update validates transitions and updates DB. Both enforce driverId ownership check.</done>
</task>
