# Plan 51-01: Fix IN_TRANSIT activation completion

## Goal
Ensure that when `first_load_in_transit` fires and pushes completionPct to 100, `ActivationProgress.isActivated` is set to `true` and a `tenant.activated` AppEvent is written — both of which are already implemented in the shared branch logic but need verification against the live tenant `7c03ff70`.

## must_haves
- [ ] The `first_load_in_transit` branch sets `isActivated: true` when `newPct === 100` (via the shared `nowActivated` flag — confirm it reaches this branch)
- [ ] A `tenant.activated` AppEvent row is written in the same transaction when `nowActivated && !current.isActivated`
- [ ] The write is idempotent: if `current.isActivated` is already `true`, no duplicate AppEvent is written
- [ ] `bypass_rls=on` SET is confirmed present before the AppEvent write
- [ ] TypeScript compiles cleanly (npx tsc --noEmit, no lint)

The fix is to re-trigger the tracker so the existing logic runs — but first confirm the code path is correct, and if it is, document that the tenant needs a one-time DB correction.
