# Plan 51-02: Add activation hook to direct driver creation

## Goal
Fire the `first_real_driver` activation event when a driver is created directly via the POST `/api/v1/carrier/fleet/drivers` route, closing the gap where only invitation-accepted drivers triggered this event.

## must_haves
- [ ] `recordActivationEvent(orgId, 'first_real_driver')` is called inside an `after()` block in the POST handler
- [ ] The `after()` block is placed after the 201 response is returned (non-blocking)
- [ ] Import of `recordActivationEvent` is present at the top of the file
- [ ] The existing `fireEvent('ON_DRIVER_CREATE')` after block is preserved unchanged
- [ ] TypeScript compiles cleanly (npx tsc --noEmit, no lint)

## Context
Drivers can reach `ActivationProgress.firstRealDriverAt` via two paths: (1) user invitation acceptance, wired in Phase 49's `accept-invitation/route.ts`, and (2) direct creation via `/carrier/fleet/drivers/new`, which posts to this route. Path 2 was never wired. The tracker is idempotent — if path 1 already fired for this tenant, the direct-create `after()` block will be a no-op. Direct-created drivers have no `isSample` flag in the schema input (sample data uses a seeder that writes directly to the DB, not this API route), so no guard is needed beyond the tracker's own idempotency.
