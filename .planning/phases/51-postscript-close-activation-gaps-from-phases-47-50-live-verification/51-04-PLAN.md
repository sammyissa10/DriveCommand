# Plan 51-04: Auto-redirect non-activated tenants on sign-in

## Goal
On successful sign-in, check whether the owner's tenant has completed activation (`ActivationProgress.isActivated`) and redirect them to `/onboarding/welcome` if not, so they land on the onboarding checklist instead of the dashboard.

## must_haves
- [ ] The `redirectUrl` for OWNER role is `/onboarding/welcome` when `ActivationProgress.isActivated === false`
- [ ] The `redirectUrl` for OWNER role is `/carrier/dashboard` when `ActivationProgress.isActivated === true`
- [ ] The check only applies to OWNER role (DRIVER and sysadmin redirect logic is unchanged)
- [ ] If no `ActivationProgress` row exists for the tenant, the redirect goes to `/onboarding/welcome` (defensive fallback)
- [ ] The check uses the `bypass_rls=on` pattern via `prisma.$transaction` + `TX_OPTIONS`
- [ ] TypeScript compiles cleanly (npx tsc --noEmit, no lint)

## Context
The login route at `apps/web/src/app/api/auth/login/route.ts` currently computes `redirectUrl` as a simple role-based switch (lines ~140-142): sysadmin → `/admin-dashboard`, DRIVER → `/home`, everyone else → `/carrier/dashboard`. Owners who haven't completed onboarding skip the welcome/checklist page entirely. The fix inserts an `ActivationProgress` query for OWNER tenants between the existing tenant/user validation block and the `redirectUrl` assignment. The query uses `bypass_rls=on` (same as `hydrateTenant`) because at this point in the request the session is established but RLS context may not be set. The `prisma` and `TX_OPTIONS` imports are already present in this file.

```typescript
import { prisma, TX_OPTIONS } from '@/lib/db/prisma';
```

Insert the following block AFTER the `dbUser.isActive` check block (after the closing `}` of the `if (!dbUser.isActive)` block, approximately line 136) and BEFORE the `const name = ...` line:

```typescript
// For OWNER role: check activation status and redirect to onboarding if not yet activated
let ownerIsActivated = true; // default to true — only override for OWNER tenants
if (appMeta.tenantId && appMeta.role === 'OWNER') {
  try {
    const activationRow = await prisma.$transaction(async (tx) => {
      await tx.$executeRaw`SELECT set_config('app.bypass_rls', 'on', TRUE)`;
      return tx.activationProgress.findUnique({
        where: { tenantId: appMeta.tenantId as string },
        select: { isActivated: true },
      });
    }, TX_OPTIONS);
    // If no row exists (defensive), treat as not-activated
    ownerIsActivated = activationRow?.isActivated ?? false;
  } catch (activationErr) {
    // Non-fatal: if the check fails, fall through to dashboard (better than blocking login)
    logger.warn('[login] ActivationProgress check failed — defaulting to dashboard', {
      tenantId: appMeta.tenantId as string,
      activationErr,
    });
    ownerIsActivated = true;
  }
}
```

Then update the `redirectUrl` assignment block (currently ~lines 140-142) to use `ownerIsActivated`:

```typescript
let redirectUrl = '/carrier/dashboard';
if (appMeta.isSystemAdmin) redirectUrl = '/admin-dashboard';
else if (appMeta.role === 'DRIVER') redirectUrl = '/home';
else if (appMeta.role === 'OWNER' && !ownerIsActivated) redirectUrl = '/onboarding/welcome';
```

The OWNER case (`!ownerIsActivated`) overrides `/carrier/dashboard` only when the tenant hasn't completed activation. All other role branches remain unchanged.
