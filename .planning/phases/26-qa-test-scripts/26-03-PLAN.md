Create docs/qa/driver-tests.md as the complete manual QA test script for the Driver portal.

KEY FACTS about the driver portal (base all tests on these):
- Driver login: /sign-in with email + password (role=DRIVER), same /sign-in page as owner
- Driver root redirects to /my-route (the assigned route page)
- My Route (/my-route): read-only view of assigned route, route docs (download-only), truck docs (download-only)
- My Load (/my-load): shows active load with status timeline, can advance status (DISPATCHED→PICKED_UP→IN_TRANSIT→DELIVERED)
- Hours (/hours): HOS dashboard showing hours remaining, duty status
- Incidents (/incidents): incident report submission form
- Messages (/messages): driver messaging interface
- My Tickets (/my-tickets): driver-submitted support tickets
- CRITICAL: Driver documents page is READ-ONLY — drivers can only VIEW/DOWNLOAD documents, NOT upload
- Drivers are BLOCKED from all owner paths (/dashboard, /trucks, /drivers, etc.)

FILE STRUCTURE:
```
# Driver Portal — QA Test Scripts
(intro: driver portal is mobile-first, login at /sign-in, role=DRIVER)

## Smoke Tests (Run First)
(5-6 critical tests)

## Section 1: Authentication (TC-DR-AUTH-xxx)
## Section 2: My Route (TC-DR-RTE-xxx)
## Section 3: My Load — Status Management (TC-DR-LOD-xxx)
## Section 4: Documents (TC-DR-DOC-xxx)
## Section 5: Hours of Service (TC-DR-HOS-xxx)
## Section 6: Incidents (TC-DR-INC-xxx)
## Section 7: Messages (TC-DR-MSG-xxx)
## Section 8: Support Tickets (TC-DR-TKT-xxx)
## Section 9: Access Boundary Tests (TC-DR-SEC-xxx)
```

Each test case uses this format:
```markdown
### TC-DR-XXX-NNN: [Title]

**Preconditions:**
- [Exact state]

**Steps:**
1. [Exact action]

**Expected Result:**
- [Observable outcome]

**Pass** [ ] **Fail** [ ]
```

- TC-DR-AUTH-002: Login with wrong password
