    - `@smoke driver can access my-route page` — goto `/my-route`, expect driver navigation visible (bottom nav with My Route, My Load, Hours, etc.)
    - `driver root URL redirects to /my-route` — goto `/`, expect redirect to `/my-route`
    - `unauthenticated user cannot access driver pages` — use `{ storageState: { cookies: [], origins: [] } }`, goto `/my-route`, expect redirect to `/sign-in`
    - `driver does not see owner sidebar` — on `/my-route`, expect owner sidebar elements (Trucks, Routes, Loads nav links) to NOT be visible

    - `@smoke assigned route page renders` — goto `/my-route`, expect page content (either route details or "No route assigned" message — both are valid)
    - `route shows stop information if assigned` — if route assigned, expect stop addresses or timeline visible
    - `route page shows map or map placeholder` — expect map container or placeholder element visible

    **e2e/driver/my-load.spec.ts** (~3 tests):
    - `@smoke my-load page renders` — goto `/my-load`, expect page content (load info or "No load" message)
    - `load status badge visible if load assigned` — if load exists, expect a status badge (DISPATCHED, IN_TRANSIT, etc.)
    - `load advancement button visible for active load` — if load is in advanceable state, expect Mark Picked Up / Mark Delivered type button

    **e2e/driver/access-boundaries.spec.ts** (~6 tests — critical for security):
    This file tests that each role CANNOT access other portals' routes.

    Driver attempting owner routes:
    - `@smoke driver cannot access /dashboard` — goto `/dashboard`, expect redirect to `/my-route` or `/sign-in` or 403
    - `driver cannot access /trucks` — goto `/trucks`, expect redirect
    - `driver cannot access /loads` — goto `/loads`, expect redirect

    Driver attempting sysadmin routes:
    - `driver cannot access /admin-dashboard` — goto `/admin-dashboard`, expect redirect to `/sign-in`

    Owner attempting sysadmin routes (use owner storageState override):
    - `owner cannot access /admin-dashboard` — test.use with owner storageState, goto `/admin-dashboard`, expect redirect to `/sign-in`

    Sysadmin attempting owner routes (use sysadmin storageState override):
    - `sysadmin accessing /dashboard behavior` — test.use with sysadmin storageState, goto `/dashboard`, document actual behavior (may redirect or show different content depending on middleware)

    NOTE: For tests with mixed roles in one file, use `test.describe` blocks with different `test.use()` per describe block. Each describe can override storageState.

    **Patterns for driver specs:**
    - Driver may or may not have assigned routes/loads in test data — tests should handle both cases gracefully
    - Use `page.locator('.some-element').or(page.getByText('No route'))` patterns to handle empty states
    - Access boundary tests should assert redirect behavior (check final URL) rather than page content

    **1. Create `.github/workflows/playwright.yml`:**
    ```yaml
    name: Playwright E2E Tests
    on:
      push:
        branches: [master]
      pull_request:
        branches: [master]
      workflow_dispatch:  # Manual trigger
    jobs:
      test:
        timeout-minutes: 30
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4
          - uses: actions/setup-node@v4
            with:
              node-version: 20
              cache: 'npm'
          - run: npm ci
          - run: npx playwright install --with-deps chromium
          - name: Run Playwright tests
            run: npx playwright test --project=chromium
            env:
              PLAYWRIGHT_BASE_URL: ${{ secrets.PLAYWRIGHT_BASE_URL }}
              TEST_OWNER_EMAIL: ${{ secrets.TEST_OWNER_EMAIL }}
              TEST_OWNER_PASSWORD: ${{ secrets.TEST_OWNER_PASSWORD }}
              TEST_SYSADMIN_EMAIL: ${{ secrets.TEST_SYSADMIN_EMAIL }}
              TEST_SYSADMIN_PASSWORD: ${{ secrets.TEST_SYSADMIN_PASSWORD }}
              TEST_DRIVER_EMAIL: ${{ secrets.TEST_DRIVER_EMAIL }}
              TEST_DRIVER_PASSWORD: ${{ secrets.TEST_DRIVER_PASSWORD }}
          - uses: actions/upload-artifact@v4
            if: ${{ !cancelled() }}
            with:
              name: playwright-report
              path: playwright-report/
              retention-days: 30
    ```
    Notes:
    - Only install chromium browser (not all browsers) to save CI time
    - `workflow_dispatch` allows manual triggering
    - Upload HTML report as artifact even on failure (for debugging)
    - CI workers=1 is already set in playwright.config.ts via `process.env.CI`
    - Secrets must be configured by the user in GitHub repo settings
