- EditRouteSheet gained TruckPickerSheet with lazy-loaded truck list and truckId in save payload

## Decisions Made
- Route list queries `status=all` always and groups client-side — avoids 4 separate queries, simpler refetch on pull-to-refresh
- Completed section defaults to collapsed since historical data is lower priority for owners
- `getTruckOptions` is a named alias of `getTrucks` (same endpoint `/api/mobile/owner/trucks`) to semantically differentiate "picker options" from "full truck management"
- Driver validation uses `tx.user` with `role: 'DRIVER'` (no separate Driver Prisma model exists)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed driver validation: tx.driver does not exist**
- **Found during:** Task 1 (POST route handler)
- **Issue:** Plan specified `tx.driver.findFirst({ where: { id: driverId, tenantId } })` but the Prisma schema has no `Driver` model — drivers are `User` records with `role: 'DRIVER'`
- **Fix:** Changed to `tx.user.findFirst({ where: { id: driverId, tenantId, role: 'DRIVER' } })` matching the pattern in the PATCH handler above
- **Files modified:** `apps/web/src/app/api/mobile/owner/routes/route.ts`
- **Verification:** `tsc --noEmit` passes with no errors
- **Committed in:** `514ad40` (Task 1 commit)

**2. [Rule 3 - Blocking] Rebuilt api-client dist after adding getTruckOptions**
- **Found during:** Task 2 TypeScript check
- **Issue:** Mobile app resolves `@drivecommand/api-client` from `dist/` (compiled output) not `src/`, so `getTruckOptions` was not visible until `npm run build` ran
- **Fix:** Ran `npm run build` in `packages/api-client` to regenerate `dist/owner.d.ts`
- **Files modified:** `packages/api-client/dist/owner.js`, `dist/owner.d.ts`, `dist/owner.d.ts.map`
- **Verification:** `cd apps/mobile && npx tsc --noEmit` passes with no errors
- **Committed in:** `514ad40` (Task 1 commit — dist is built artifact, not committed separately)
