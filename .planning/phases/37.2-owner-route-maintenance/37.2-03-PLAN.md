Create `apps/mobile/app/(owner)/routes/new.tsx` — a two-step route creation form per user decision: "step-by-step or bottom-sheet style entry".

**Screen structure:**
- SafeAreaView + AnimatedScreen wrapper (matches all other screens).
- Header with back arrow + title "Create Route" + step indicator ("Step 1 of 2" / "Step 2 of 2").
- Step state: `const [step, setStep] = useState<1 | 2>(1)`.

**Step 1 — Basic Info:**
- Route Name: TextInput (required, same inputStyle as other forms in this app).
- Driver picker: Pressable that shows selected driver name or "Select Driver". On press, opens a DriverPickerSheet (reuse the pattern from routes/[id].tsx — inline BottomSheet with driver list from `ownerApi.getActiveDrivers`). Store `selectedDriverId` and `selectedDriverName` in state.
- Truck picker: Same pattern — Pressable showing selected truck or "Select Truck". On press, opens TruckPickerSheet (inline BottomSheet listing trucks from `ownerApi.getTrucks`). Each truck row shows `{year} {make} {model} — {licensePlate}` with a status indicator dot (green=Ready, amber=In Maintenance, etc). Store `selectedTruckId` and `selectedTruckLabel` in state.
- Scheduled Date (optional): TextInput with YYYY-MM-DD format, pre-filled with today's date.
- "Next" button at bottom — enabled only when name, driver, and truck are selected. On press: `haptic.light(); setStep(2)`.

**Step 2 — Stops Management:**
- Instruction text: "Add at least 2 stops (pickup and delivery points)".
- Stop list: Each stop is a row with:
  - Position number (1, 2, 3...).
  - Type toggle: Pressable cycling between PICKUP and DELIVERY (show as small badge).
  - AddressInput component (import from `@/components/owner/AddressInput`) for address entry.
  - Wrapped in `Swipeable` from `react-native-gesture-handler` for swipe-to-delete:
    - `renderRightActions` returns a red "Delete" action view.
    - On swipe complete: remove stop from array, haptic.light().
    - Cannot delete if only 2 stops remain — disable swipe or show toast warning.
  - **Z-index handling for AddressInput dropdowns**: Render stops in reverse z-index order — first stop gets highest zIndex (e.g., `zIndex: 1000 - index`). This prevents dropdown clipping from later rows. Do NOT use overflow:hidden on stop row containers.
- "Add Stop" button below the stop list: adds a new stop entry to the array with default type DELIVERY and empty address.
- Initial state: 2 stops — first with type PICKUP, second with type DELIVERY.
- Store stops in state: `const [stops, setStops] = useState<Array<{ address: string; type: 'PICKUP' | 'DELIVERY' }>>([{ address: '', type: 'PICKUP' }, { address: '', type: 'DELIVERY' }])`.

**Submit button:**
- At bottom of Step 2: "Create Route" button.
- Validates: all stops must have non-empty addresses. If validation fails, show Toast error.
- On press: `haptic.medium()`, call `ownerApi.createRoute(token!, { name, driverId: selectedDriverId!, truckId: selectedTruckId!, scheduledDate, stops: stops.map(s => ({ address: s.address, type: s.type })) })` via useMutation.
- onSuccess: `haptic.success()`, Toast success, invalidate `['owner-routes']` query, `router.back()`.
- onError: `haptic.error()`, Toast error with message.
- Show ActivityIndicator while submitting, disable button.

**Back navigation:**
- Step 2 back arrow goes to Step 1 (not router.back()).
- Step 1 back arrow does router.back().

**Patterns to follow:**
- `useThemeColors()` for all colors.
- `useAuthContext()` for token.
- KeyboardAvoidingView wrapping the ScrollView content.
- All Pressables have `active:opacity-75` feedback.
- Import `haptic` from `@/lib/haptics`.
