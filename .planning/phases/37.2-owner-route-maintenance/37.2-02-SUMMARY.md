## What Was Built

### Task 1: ScheduledService API Endpoints

**`/api/mobile/owner/trucks/[id]/scheduled-service`** (GET, POST, PATCH):
- GET: returns non-completed scheduled services for a truck with computed `dueDate`, `dueMileage`, and `status`
- POST: accepts `{ serviceType, dueDate?, dueMileage?, notes? }`, converts to `intervalDays`/`intervalMiles` relative to baseline
- PATCH: marks service complete + creates `MaintenanceEvent` as immutable audit trail

**`/api/mobile/owner/maintenance`** (GET):
- Returns all non-completed scheduled services across all trucks for the tenant
- Includes full truck info (`id`, `make`, `model`, `licensePlate`, `odometer`) in each response item
- Same status computation logic (overdue/due_soon/ok)

All endpoints follow standard mobile API pattern: `validateMobileToken` + OWNER role check + rate limit + `bypass_rls` transaction.

**Status thresholds:**
- `overdue`: past due date OR current odometer >= due mileage
- `due_soon`: within 7 days of due date OR within 500 miles of due mileage
- `ok`: everything else

### Task 2: api-client Types + Methods + Constants
