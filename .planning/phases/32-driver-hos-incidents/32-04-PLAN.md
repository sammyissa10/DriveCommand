   - category must be one of: ACCIDENT, VIOLATION, MECHANICAL, HAZARD, OTHER. Return 400 if invalid.
   - severity must be one of: LOW, MEDIUM, HIGH. Return 400 if invalid.
   - description must be a string with length >= 10 and <= 500. Return 400 if invalid.
   - latitude/longitude: optional, if provided must be numbers

   - Create DriverIncident:
     ```
     {
       tenantId,
       driverId,
       category: category as IncidentCategory,
       severity: severity as IncidentSeverity,
       description,
       latitude: latitude ?? null,
       longitude: longitude ?? null,
       photoS3Key: photoS3Key ?? null,
       reportedAt: new Date(),
     }
     ```
5. Return 201 with `{ incident: createdIncident }`

Note: The api-client `createIncident` method was already added in plan 32-02 task 3.

**upload.ts — Photo upload to S3 via existing multipart API:**

```typescript
export async function uploadPhotoToS3(
  uri: string,
  token: string,
  onProgress?: (percent: number) => void
): Promise<string>
```

Implementation:
1. Read the file using `expo-file-system` to get file info (size, name)
2. Call POST `/api/documents/multipart/initiate` with `{ fileName: 'incident-photo.jpg', contentType: 'image/jpeg', sizeBytes }` and Bearer token
3. This returns `{ uploadId, s3Key, parts: [{ partNumber, presignedUrl }] }`
4. For each part, upload the file chunk via fetch PUT to the presigned URL. For a single photo (<5MB), there will be 1 part.
5. Call POST `/api/documents/multipart/complete` with `{ uploadId, s3Key, parts: [{ partNumber, etag }] }` and Bearer token
6. Return the s3Key
7. Call onProgress at each step (33% after initiate, 66% after upload, 100% after complete)

Use the api-client's getBaseUrl pattern for the API calls, or use fetch directly with the token header.
