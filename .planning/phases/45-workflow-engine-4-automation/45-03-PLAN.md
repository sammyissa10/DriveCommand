**Part A — DISPATCH_READY on ready-flag flip** (`computeDispatchReadiness.ts`):

Read the current file. It computes readiness and writes to `User.isDispatchReady` (and `Truck.isDispatchReady` per Phase 44). The fix: before the write, fetch the current value; if the write flips it from `false` to `true`, call `sendDispatchReady({ userId, tenantId, playbookInstanceId })` AFTER the write completes.

Pattern:

```typescript
// Before updating readiness:
const current = await prisma.user.findUnique({ where: { id: userId }, select: { isDispatchReady: true } });

// ...existing update logic to compute newIsDispatchReady...

await prisma.user.update({ where: { id: userId }, data: { isDispatchReady: newIsDispatchReady } });

// Fire notification only on false → true flip
if (current?.isDispatchReady === false && newIsDispatchReady === true) {
  try {
    await sendDispatchReady({ userId, tenantId, playbookInstanceId });
  } catch (err) {
    logger.error('[computeDispatchReadiness] sendDispatchReady failed', { userId, err });
  }
}
```

**Important:** `computeDispatchReadiness` is called on every step completion, which means it may be invoked many times while readiness is already true. The `false → true` gate must be strict — do NOT send on repeated `true → true` calls, or dispatchers will get notification spam.
