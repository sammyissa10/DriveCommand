# Driver My Route — Technical Reference

<Callout variant="warning">
Internal engineering documentation. For user-facing docs, see the client Help Center.
</Callout>

## Overview

Driver My Route displays multi-stop route assignments with all pickups and deliveries in sequence order. It integrates Load, RouteStop, Route, and Truck data into a single timeline view with route-level messaging.

**Portal:** Driver (mobile app)
**Route:** `/driver/my-route`
**Plan Tier:** Pro
**Added:** v2.0.0 (Phase 37.1)

## Stop Sequence Logic

RouteStop.sequence determines timeline order. Stops are always displayed in ascending sequence order.

<CodeBlock language="typescript">
{`// Query from endpoint
const route = await prisma.route.findFirst({
  where: {
    tenantId: currentUser.tenantId,
    loads: {
      some: {
        driverId: currentUser.id,
        status: { notIn: ['DELIVERED', 'CANCELLED'] }
      }
    }
  },
  include: {
    truck: true,
    stops: {
      orderBy: { sequence: 'asc' }, // Critical for timeline order
      include: {
        load: true
      }
    }
  }
});`}
</CodeBlock>

**Sequence modification:** Only dispatch (owner portal) can reorder stops. Drivers cannot skip stops or change sequence.

## Route vs. Load Messaging

**Two message scopes:**

1. **Load messages** (`FleetMessage.loadId`) — Specific to one shipment
2. **Route messages** (`FleetMessage.routeId`) — Multi-stop trip coordination

**When to use route messages:**
- ETA changes affecting multiple stops
- Truck issues (breakdown, flat tire)
- Sequence change requests
- General trip-level questions

**When to use load messages:**
- Questions about specific freight
- BOL/PO issues
- Single-stop delays

Mobile UI separates these into different threads.

## Stop Completion Status

`isCompleted` is computed server-side based on Load.status and stop type:

<CodeBlock language="typescript">
{`function computeStopCompletion(
  stop: RouteStop & { load: Load }
): boolean {
  if (!stop.load) return false;

  if (stop.type === 'PICKUP') {
    return ['PICKED_UP', 'IN_TRANSIT', 'DELIVERED'].includes(stop.load.status);
  }

  if (stop.type === 'DELIVERY') {
    return stop.load.status === 'DELIVERED';
  }

  return false;
}`}
</CodeBlock>

**Visual indicators in mobile app:**
- Green checkmark = completed
- Blue dot = current stop
- Gray dot = upcoming

## Truck Details

Truck info is read-only in the driver app. Odometer and fuel level are last-reported values (updated via mobile GPS reports or manual entry in owner portal).

**Fields displayed:**
- unitNumber, make, model, year
- licensePlate, VIN
- odometerReading (last reported)
- fuelLevel (last reported %, nullable)

## Security

<Callout variant="danger" title="Route Access Control">
Drivers can only view routes where at least one Load in the route has `driverId` matching the authenticated user. Never expose routes for other drivers.
</Callout>

**Validation pattern:**

<CodeBlock language="typescript">
{`const route = await prisma.route.findUnique({
  where: { id: routeId },
  include: {
    loads: { where: { driverId: currentUser.id } }
  }
});

if (!route || route.loads.length === 0) {
  throw new Error('Forbidden: Not assigned to this route');
}`}
</CodeBlock>

## Performance Considerations

- **Single query:** Route + Truck + Stops + Loads fetched with one Prisma include
- **Caching:** Route data cached for 60s in Redis (longer than dashboard due to less frequent changes)
- **Stop limit:** Routes with > 20 stops may paginate (rare in trucking)

**Index:** `@@index([routeId, sequence])` on RouteStop for fast ordered retrieval.

## Troubleshooting

**Driver can't see My Route screen:**

1. Verify Load.routeId is not null (single loads without multi-stop routes don't show My Route)
2. Check Route.status is IN_PROGRESS (COMPLETED/CANCELLED routes are hidden)
3. Confirm driver is assigned to at least one load in the route

**Stop sequence is wrong:**

1. Check RouteStop.sequence values in DB (should be 1, 2, 3, ...)
2. Verify query uses `orderBy: { sequence: 'asc' }`
3. Sequence gaps are allowed (e.g., 1, 3, 5) — still displays in order

**Route messages not appearing:**

1. Verify FleetMessage.routeId matches the route
2. Check senderId/recipientId — route messages should have recipientId = null (broadcast to dispatch)
3. Confirm tenantId matches
