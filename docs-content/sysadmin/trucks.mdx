# Legacy Truck Management — Technical Reference

<Callout variant="warning">
This documentation is for internal engineering use. For user-facing documentation, see the client Help Center article on legacy truck management.
</Callout>

## Overview

The legacy truck management subsystem provides CRUD operations for fleet vehicles, document tracking, maintenance scheduling, and automated status badge computation. Route: `/trucks`.

This is distinct from the newer Carrier Truck Management feature (`/carrier/fleet/trucks`), which shares the same database models but provides an enhanced UI.

## Auto-Status Badge Computation

Truck status badges are computed dynamically based on business rules. The `getTruckStatus()` utility function runs these checks:

<ProcessDiagram steps={[
  { label: "Expired Docs", description: "One or more Document records with expiryDate < now()" },
  { label: "In Maintenance", description: "maintenanceStatus === 'IN_MAINTENANCE'" },
  { label: "In Use", description: "Assigned to an active Route (route.status !== 'COMPLETED')" },
  { label: "Ready to Use", description: "None of the above conditions match" }
]} />

Status badge computation is deterministic and happens at query time. No status field is persisted in the Truck table.

<CodeBlock language="typescript">
{`// Status badge computation
export function getTruckStatus(truck: TruckWithRelations): TruckStatus {
  // Check document expiry
  const hasExpiredDocs = truck.documents.some(
    (doc) => new Date(doc.expiryDate) < new Date()
  );
  if (hasExpiredDocs) return TruckStatus.EXPIRED_DOCS;

  // Check maintenance flag
  if (truck.maintenanceStatus === 'IN_MAINTENANCE') {
    return TruckStatus.IN_MAINTENANCE;
  }

  // Check active route assignment
  const activeRoute = truck.routes.find(
    (route) => route.status !== RouteStatus.COMPLETED
  );
  if (activeRoute) return TruckStatus.IN_USE;

  // Default: available
  return TruckStatus.READY_TO_USE;
}`}
</CodeBlock>

## Document Tracking

Each truck requires three core Document types: REGISTRATION, INSURANCE, ANNUAL_INSPECTION. Document expiry checks run via cron job at `/api/cron/send-reminders`:

- **30 days before expiry**: Yellow warning email sent to tenant owner
- **7 days before expiry**: Red alert email sent to tenant owner
- **After expiry**: Truck status badge changes to EXPIRED_DOCS

Documents are stored in Cloudflare R2 with presigned URL access.

<CodeBlock language="typescript">
{`// Upload truck document
export async function uploadTruckDocument(
  truckId: string,
  file: File,
  documentType: DocumentType,
  expiryDate: Date
) {
  const tenantId = await requireTenantId();
  const prisma = await getTenantPrisma();

  // Upload to R2
  const fileKey = await uploadToR2(file, tenantId);

  // Create document record
  const document = await prisma.document.create({
    data: {
      tenantId,
      truckId,
      type: documentType,
      fileName: file.name,
      fileKey,
      expiryDate,
    },
  });

  return document;
}`}
</CodeBlock>

## Scheduled Maintenance

ScheduledService model tracks preventive maintenance:

- **Date-based**: Service due on specific date
- **Mileage-based**: Service due at odometer reading

When a scheduled service comes due, the cron job automatically sets `maintenanceStatus = 'IN_MAINTENANCE'` and sends notification to tenant owner.

## Security Considerations

<Callout variant="danger" title="Document Access">
Presigned URLs for truck documents expire after 1 hour. Never expose permanent R2 URLs in client-facing code.
</Callout>

<Callout variant="warning" title="VIN Uniqueness">
VIN field has a unique constraint across the entire platform (not just per tenant) to prevent fraud. Duplicate VIN attempts will fail with database error.
</Callout>

## Performance Considerations

Status badge computation requires joining Document, Route, and ScheduledService tables. For large fleets (500+ trucks), consider:

- Caching computed statuses in Redis with 5-minute TTL
- Using database indexes on `tenantId + isActive` for active truck queries
- Paginating truck lists at 50 items per page

## Troubleshooting

**Truck stuck in "In Maintenance" status:**

Check `truck.maintenanceStatus` field. If still set to `IN_MAINTENANCE`, call `markTruckAvailable()` action to reset.

**Status badge showing "Expired Docs" incorrectly:**

Query `Document` table for that truck and verify expiry dates. Check that cron job `/api/cron/send-reminders` is running daily.
