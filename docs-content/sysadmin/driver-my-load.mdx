# Driver My Load — Technical Reference

<Callout variant="warning">
Internal engineering documentation. For user-facing docs, see the client Help Center.
</Callout>

## Overview

Driver My Load provides mobile drivers with current load details and status update controls. The feature enforces a forward-only state machine (PENDING → PICKED_UP → IN_TRANSIT → DELIVERED) and emits real-time events to notify dispatch of progress.

**Portal:** Driver (mobile app)
**Route:** `/driver/my-load`
**Plan Tier:** Pro
**Added:** v2.0.0 (Phase 31)

### PATCH /api/mobile/driver/loads/[id]/status

Updates load status to the next valid state.

**Auth:** Bearer token required
**Role:** DRIVER

<CodeBlock language="typescript">
{`// Request
PATCH /api/mobile/driver/loads/[id]/status
{
  "status": "PICKED_UP"
}

// Response
{
  "load": {
    "id": "uuid",
    "status": "PICKED_UP",
    "statusUpdatedAt": "2024-05-09T08:15:00Z"
  }
}`}
</CodeBlock>

**Validation:**
- Status must be next in sequence (cannot skip or rollback)
- Driver must be assigned to the load
- Timestamp is server-generated (client cannot spoof)

**Side effects:**
- Push notification sent to dispatch
- Load.updatedAt timestamp updated
- FleetMessage auto-created (optional, configurable)

### Transition Rules

<CodeBlock language="typescript">
{`// Server-side validation
const VALID_TRANSITIONS: Record<LoadStatus, LoadStatus[]> = {
  PENDING: ['PICKED_UP'],
  PICKED_UP: ['IN_TRANSIT'],
  IN_TRANSIT: ['DELIVERED'],
  DELIVERED: [], // Terminal state
  CANCELLED: [] // Terminal state
};

export function validateStatusTransition(
  currentStatus: LoadStatus,
  newStatus: LoadStatus
): boolean {
  return VALID_TRANSITIONS[currentStatus]?.includes(newStatus) ?? false;
}`}
</CodeBlock>

**CANCELLED status:** Only dispatch (via owner portal) can cancel loads. Drivers cannot cancel or revert statuses.

## Offline Queue Support

The mobile app queues status updates when offline and flushes when reconnected.

<CodeBlock language="typescript">
{`// Mobile implementation (apps/mobile)
import { callOrQueue } from '@/lib/offline/queue';

async function updateLoadStatus(loadId: string, status: LoadStatus) {
  await callOrQueue({
    key: \`update-load-\${loadId}\`,
    fn: () => driverApi.updateLoadStatus(loadId, status),
    dedupe: true // Only keep latest status update per load
  });
}`}
</CodeBlock>

Queued updates flush with exponential backoff (1s, 2s, 4s, 8s) on reconnection.

## Real-time Notifications

When a driver updates load status, dispatch receives a push notification.

<CodeBlock language="typescript">
{`// From PATCH /api/mobile/driver/loads/[id]/status
import { sendPushToUser } from '@/lib/push/send';

// After successful status update
const dispatchUsers = await prisma.user.findMany({
  where: {
    tenantId: load.tenantId,
    role: { in: ['OWNER', 'MANAGER'] }
  }
});

for (const user of dispatchUsers) {
  await sendPushToUser(user.id, {
    title: \`Load \${load.loadNumber} Updated\`,
    body: \`Driver advanced status to \${newStatus}\`,
    data: {
      type: 'LOAD_STATUS_UPDATE',
      loadId: load.id,
      url: \`/carrier/loads/\${load.id}\`
    }
  });
}`}
</CodeBlock>

## Performance Considerations

- **Stop timeline:** Uses Prisma `include` to fetch RouteStop in single query
- **Status index:** `@@index([tenantId, status, driverId])` for fast active load queries
- **Cache invalidation:** Status updates clear Redis cache for dashboard/loads list

**Optimization:** Consider using Prisma transactions for status updates to ensure atomicity when updating Load + RouteStop.completedAt simultaneously.

## Security

<Callout variant="danger" title="Driver Isolation">
Drivers can ONLY view and update loads where `driverId` matches their authenticated user ID. Always validate ownership before returning load data or accepting status updates.
</Callout>

<CodeBlock language="typescript">
{`// Example ownership check
const load = await prisma.load.findUnique({ where: { id: loadId } });

if (load.driverId !== currentUser.id) {
  throw new Error('Forbidden: Not assigned to this load');
}`}
</CodeBlock>

## Troubleshooting

**Status update returns 400 "Invalid transition":**

1. Check current load status in DB
2. Verify requested status is next in sequence
3. Ensure load is not in DELIVERED or CANCELLED state

**Driver can't see their load:**

1. Verify Load.driverId matches User.id
2. Check tenant isolation — Load.tenantId === User.tenantId
3. Confirm status is not CANCELLED

**Offline queue not syncing:**

1. Check NetInfo reconnection event listener in mobile app
2. Verify queued mutation key matches pattern in MMKV storage
3. Check exponential backoff retry count (max 5 retries)
