# SysAdmin Knowledge Base — Technical Reference

<Callout variant="warning">
Internal engineering documentation. This is meta-documentation — docs about the docs system itself.
</Callout>

## Overview

The SysAdmin Knowledge Base provides technical reference documentation for all DriveCommand features, visible only to SysAdmin users. Key features:

- **MDX documentation** — technical docs in `docs-content/sysadmin/` directory
- **Feature registry integration** — auto-links features to docs via slug matching
- **Admin search** — client-side search with fuse.js (fuzzy matching)
- **Sysadmin-specific content** — server actions, Prisma models, RLS policies, cron jobs
- **Component library** — shared MDX components (Callout, CodeBlock, PrismaModelRef, etc.)

This is the documentation system you're reading right now.

**Data flow:**
1. Sysadmin navigates to `/sysadmin/docs`
2. Server loads all MDX files from `docs-content/sysadmin/`
3. Client builds search index from frontmatter + content
4. User searches → fuse.js fuzzy match → results filtered by relevance
5. User clicks result → MDX rendered with React components

## Search Implementation

**Client-side search with fuse.js:**

<CodeBlock language="typescript">
{`// Search configuration
const fuseOptions = {
  keys: [
    { name: 'title', weight: 3 },
    { name: 'summary', weight: 2 },
    { name: 'content', weight: 1 },
  ],
  threshold: 0.3,  // 0 = exact match, 1 = match anything
  includeScore: true,
};

const fuse = new Fuse(docs, fuseOptions);

function search(query: string) {
  const results = fuse.search(query);
  return results.slice(0, 20); // Top 20 results
}`}
</CodeBlock>

**Search features:**
- Fuzzy matching (typo-tolerant)
- Weighted fields (title > summary > content)
- Instant results (no server round-trip)
- Highlight matching text

## Adding a New Doc

1. **Check feature registry** — ensure feature has `requiresSysadminDoc: true`

2. **Copy template:**

<CodeBlock language="bash">
{`cp docs-content/sysadmin/_template.mdx docs-content/sysadmin/my-feature.mdx`}
</CodeBlock>

3. **Fill in frontmatter:**
   - `slug` must match feature registry
   - `title` includes "— Technical Reference"
   - `summary` is 1-2 sentences, max 300 chars
   - `lastReviewed` is today's date
   - `estimatedReadMinutes` is word count ÷ 200

4. **Write content:**
   - Follow template structure (Overview, Server Actions, Database Schema, etc.)
   - Use MDX components (Callout, CodeBlock, PrismaModelRef)
   - Include code examples and troubleshooting section

5. **Verify build:**

<CodeBlock language="bash">
{`npm run build
# Should succeed with no errors`}
</CodeBlock>

6. **Commit:**

<CodeBlock language="bash">
{`git add docs-content/sysadmin/my-feature.mdx
git commit -m "docs: add sysadmin doc for my-feature"`}
</CodeBlock>

## Content Guidelines

**Technical depth:**
- Assume reader is an engineer familiar with TypeScript/Prisma/Next.js
- Include server action signatures, Prisma models, RLS policies
- Document edge cases, security considerations, performance notes

**Code examples:**
- Always include realistic examples (not "// TODO")
- Show both TypeScript and SQL where applicable
- Use `copyable={false}` for read-only SQL queries

**Security notes:**
- Use `danger` variant Callout for critical security issues
- Document when to use `bypass_rls` (almost never)
- Explain auth requirements (SYSADMIN, Bearer token, etc.)

**Word count:**
- Aim for 300-700 words per doc (2-4 minute read)
- Complex features can be longer (e.g., tenant-management is 1200 words)

## Security Considerations

<Callout variant="danger" title="SYSADMIN Access Only">
All docs in `/sysadmin/docs` require SYSADMIN role. Middleware enforces this at route level. Do NOT expose technical docs to regular users.
</Callout>

**No sensitive data:**
- Docs should NOT include API keys, passwords, or PII
- Runbook URLs can point to Notion (access-controlled separately)

## Performance Considerations

- All MDX files loaded at build time (static generation)
- Search index built client-side (no server load)
- Typical search query: < 50ms

## Troubleshooting

**Issue: Build fails with "Missing required doc"**

Check:
1. Feature registry has `requiresSysadminDoc: true`
2. Doc file exists at `docs-content/sysadmin/{slug}.mdx`
3. Frontmatter `slug` matches feature registry `slug` exactly

**Issue: Doc not showing in search**

Verify:
1. Frontmatter is valid YAML
2. `slug` field is present
3. File is in `docs-content/sysadmin/` directory
4. Build succeeded (check for MDX parse errors)

**Issue: MDX component not rendering**

Check:
1. Component is imported in `MDXProvider`
2. Props match component signature
3. No JSX syntax errors (curly braces, quotes)
