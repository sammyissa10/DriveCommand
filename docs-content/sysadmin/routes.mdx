## Overview

The route planning subsystem manages multi-stop routes with sequential leg ordering, driver/truck assignment, load linkage, and continuity validation. Route: `/routes`.

Routes organize multiple RouteStops into a logical sequence for dispatch. The system validates that pickups occur before their corresponding deliveries and warns on inefficient sequencing.

## Leg Sequencing Logic

Routes are divided into **legs** — segments between consecutive stops. The `reorderRouteStops` action updates the `sequence` field on all stops and recalculates leg distances.

  { label: "Leg 2", description: "Stop 1 → Stop 2 (sequence: 2)" },
  { label: "Leg 3", description: "Stop 2 → Stop 3 (sequence: 3)" },
  { label: "Leg N", description: "Stop N-1 → Stop N (sequence: N)" }
]} />

<CodeBlock language="typescript">
{`// Reorder route stops
export async function reorderRouteStops(
  routeId: string,
  stopIds: string[]
): Promise<ActionState<RouteStop[]>> {
  await requireRole([UserRole.OWNER, UserRole.MANAGER]);
  const prisma = await getTenantPrisma();

  // Update sequence field for each stop
  const updates = stopIds.map((stopId, index) =>
    prisma.routeStop.update({
      where: { id: stopId },
      data: { sequence: index + 1 },
    })
  );

  const stops = await prisma.$transaction(updates);

  // Recalculate total route distance
  await recalculateRouteDistance(prisma, routeId);

  return { success: true, data: stops };
}`}
</CodeBlock>

## Continuity Validation

The `validateRouteContinuity` action checks that pickups occur before their corresponding deliveries. It uses `loadId` to match pickup/delivery pairs.

<CodeBlock language="typescript">
{`// Validate route continuity
export async function validateRouteContinuity(
  routeId: string
): Promise<ActionState<ValidationResult>> {
  const prisma = await getTenantPrisma();

  const stops = await prisma.routeStop.findMany({
    where: { routeId },
    orderBy: { sequence: 'asc' },
  });

  const warnings: string[] = [];

  // Group stops by loadId
  const loadStops = new Map<string, RouteStop[]>();
  for (const stop of stops) {
    if (stop.loadId) {
      if (!loadStops.has(stop.loadId)) {
        loadStops.set(stop.loadId, []);
      }
      loadStops.get(stop.loadId)!.push(stop);
    }
  }

  // Check each load's pickup comes before delivery
  for (const [loadId, loadStopsArray] of loadStops) {
    const pickup = loadStopsArray.find((s) => s.stopType === StopType.PICKUP);
    const delivery = loadStopsArray.find((s) => s.stopType === StopType.DELIVERY);

    if (pickup && delivery && pickup.sequence > delivery.sequence) {
      warnings.push(
        \`Load \${loadId}: Delivery stop (seq \${delivery.sequence}) comes before pickup (seq \${pickup.sequence})\`
      );
    }
  }

  return {
    success: true,
    data: { isValid: warnings.length === 0, warnings },
  };
}`}
</CodeBlock>

Warnings are displayed in the UI as red alerts. Routes with continuity errors can still be saved but cannot be dispatched until resolved.

## Load Linkage

When a load is assigned to a route, the system creates or updates RouteStop records automatically:

1. **Pickup stop**: Created with `stopType: PICKUP`, address from `load.origin`, `loadId` FK
2. **Delivery stop**: Created with `stopType: DELIVERY`, address from `load.destination`, `loadId` FK

The Load model maintains reverse FKs: `pickupStopId` and `deliveryStopId` for fast lookups.

<CodeBlock language="typescript">
{`// Sync RouteStops when load is assigned to route
export async function syncRouteStopsForLoad(
  prisma: PrismaClient,
  load: Load
): Promise<void> {
  if (!load.routeId) return;

  // Create or update pickup stop
  const pickupStop = await prisma.routeStop.upsert({
    where: { id: load.pickupStopId || 'new' },
    create: {
      tenantId: load.tenantId,
      routeId: load.routeId,
      loadId: load.id,
      stopType: StopType.PICKUP,
      address: load.origin,
      lat: load.pickupLat,
      lng: load.pickupLng,
      scheduledTime: load.pickupDate,
      sequence: 999, // Placeholder, reordered later
    },
    update: {
      address: load.origin,
      lat: load.pickupLat,
      lng: load.pickupLng,
      scheduledTime: load.pickupDate,
    },
  });

  // Create or update delivery stop
  const deliveryStop = await prisma.routeStop.upsert({
    where: { id: load.deliveryStopId || 'new' },
    create: {
      tenantId: load.tenantId,
      routeId: load.routeId,
      loadId: load.id,
      stopType: StopType.DELIVERY,
      address: load.destination,
      lat: load.deliveryLat,
      lng: load.deliveryLng,
      scheduledTime: load.deliveryDate,
      sequence: 1000, // Placeholder
    },
    update: {
      address: load.destination,
      lat: load.deliveryLat,
      lng: load.deliveryLng,
      scheduledTime: load.deliveryDate,
    },
  });

  // Update load with stop IDs
  await prisma.load.update({
    where: { id: load.id },
    data: {
      pickupStopId: pickupStop.id,
      deliveryStopId: deliveryStop.id,
    },
  });
}`}
</CodeBlock>

## Performance Considerations

Route queries with stops can be expensive for routes with 50+ stops. Use pagination:

<CodeBlock language="typescript">
{`// Paginated route stop query
const stops = await prisma.routeStop.findMany({
  where: { routeId },
  orderBy: { sequence: 'asc' },
  take: 20,
  skip: page * 20,
});`}
</CodeBlock>

Consider caching route distance calculations in Redis with 15-minute TTL.

## Troubleshooting

**Continuity warnings not clearing:**

Run `validateRouteContinuity()` manually. Check that pickup stops have lower `sequence` than delivery stops for the same `loadId`.

**Stops not appearing in correct order:**

Check `sequence` field on RouteStop records. Call `reorderRouteStops()` to re-sequence.

**Load not linking to route:**

Verify `load.routeId` is set. Call `syncRouteStopsForLoad()` to create missing RouteStop records.
