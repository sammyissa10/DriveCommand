# Team Permissions — Technical Reference

<Callout variant="warning">
Internal engineering documentation. For user-facing docs, see the client Help Center.
</Callout>

## Overview

The Team Permissions subsystem provides role-based access control (RBAC) with four primary roles: Owner, Manager, Dispatcher, Driver. Supports granular permission configuration and secure invitation workflow.

**Key components:**
- Server actions in `src/actions/settings/team.ts`
- User Prisma model
- Role guards (`requireRole`, `requirePermission`)
- Invitation flow (DriverInvitation model)

### `inviteTeamMember()`

Sends an invitation email with pre-configured permissions.

<CodeBlock language="typescript">
{`export async function inviteTeamMember(
  prevState: ActionState | null,
  formData: FormData
): Promise<ActionState<User>> {
  await requireRole([UserRole.OWNER]);
  const tenantId = await requireTenantId();
  const prisma = await getTenantPrisma();

  const parsed = InviteTeamMemberSchema.parse({
    email: formData.get('email'),
    name: formData.get('name'),
    role: formData.get('role'),
    permissions: JSON.parse(formData.get('permissions') || '[]'),
  });

  // Create invitation token
  const token = crypto.randomUUID();
  await prisma.driverInvitation.create({
    data: {
      tenantId,
      email: parsed.email,
      role: parsed.role,
      permissions: parsed.permissions,
      token,
      expiresAt: new Date(Date.now() + 7 * 24 * 60 * 60 * 1000), // 7 days
      invitedBy: 'owner',
    },
  });

  // Send invitation email
  await sendInvitationEmail({
    email: parsed.email,
    name: parsed.name,
    invitationUrl: \`\${process.env.NEXT_PUBLIC_BASE_URL}/accept-invitation?token=\${token}\`,
  });

  return { success: true, data: { email: parsed.email } };
}`}
</CodeBlock>

## Security Considerations

<Callout variant="danger" title="Critical: app_metadata">
User roles are stored in Supabase Auth \`app_metadata\`, NOT \`user_metadata\`. Always read from \`app_metadata\` to prevent role escalation attacks.
</Callout>

## Performance Considerations

- Permission checks are synchronous (no caching)
- For high-traffic routes, consider caching permissions in JWT claims

## Troubleshooting

**Issue: User cannot access feature**

**Cause:** Missing permission or incorrect role.

**Fix:** Check user permissions array. Grant required permission via team settings.
