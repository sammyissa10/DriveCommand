# Dispatch Checklists

<Callout variant="info">
Dispatch Checklists are pre-configured workflows that auto-start when you dispatch a load. They ensure drivers complete required verification steps — document checks, inspections, signatures — before they can mark a load "In Transit".
</Callout>

## What this solves

**The problem:** Drivers leave the yard without proper documentation, miss pre-trip inspections, or forget to verify load details. You find out hours later when there's a problem on the road or at delivery.

**The solution:** Create a checklist of required steps. When you dispatch a load, the checklist auto-starts and the driver must complete all blocking steps before they can update the load status. Nothing gets missed.

## How it works

1. **You create a checklist template** with the steps drivers must complete
2. **You enable auto-start** so it triggers on load dispatch
3. **Driver gets a notification** when assigned a load: "Complete Pre-Trip Checklist"
4. **Driver completes each step** — uploading documents, taking photos, signing acknowledgments
5. **Load status is blocked** until all required steps are done
6. **Driver marks load "In Transit"** only after checklist is complete

The checklist becomes a documented record of what was verified before departure.

## Creating a Dispatch Checklist

<StepFlow>
  <StepFlow.Step title="Navigate to Checklists">
    Go to **Workflows → Checklists & Workflows** in the sidebar.
  </StepFlow.Step>
  <StepFlow.Step title="Click Create New Playbook">
    The playbook builder opens.
  </StepFlow.Step>
  <StepFlow.Step title="Set entity type to Dispatch">
    Select **DISPATCH** as the entity type. This tells the system this checklist applies to loads.
  </StepFlow.Step>
  <StepFlow.Step title="Name your checklist">
    Give it a clear name: "Pre-Trip Inspection", "Load Acceptance Checklist", "Hazmat Verification".
  </StepFlow.Step>
  <StepFlow.Step title="Add steps">
    Click **Add Step** and configure each verification step (see Step Types below).
  </StepFlow.Step>
  <StepFlow.Step title="Mark blocking steps">
    Toggle **Required Before Dispatch** on steps that must be completed before the driver can mark the load "In Transit".
  </StepFlow.Step>
  <StepFlow.Step title="Enable auto-start rule">
    Go to **Workflows → Automation** and enable the "Pre-Trip Inspection" recipe (ON_DISPATCH_CREATE trigger).
  </StepFlow.Step>
</StepFlow>

### Inspection Items (Pass/Fail)

Inspection Items are special: they present the driver with PASS or FAIL buttons.

**On PASS:** The step is marked complete and the checklist advances.

**On FAIL:**
1. Driver must take a photo documenting the issue
2. Driver can add a note explaining the problem
3. The system automatically creates an APPROVAL step assigned to a mechanic
4. The load becomes **blocked** until the mechanic signs off on the repair
5. Dispatcher and mechanic receive notifications

This flow ensures failed inspection items get documented and fixed before the truck leaves.

<Callout variant="warning" title="Inspection Failures Block Dispatch">
When a driver fails an inspection item, the load cannot proceed until a mechanic approves the repair. This prevents trucks with safety issues from leaving the yard.
</Callout>

## Dispatch Blocking

Steps marked **Required Before Dispatch** (dispatch blockers) prevent the driver from updating the load status until completed.

**How it works:**
- Driver tries to mark load "In Transit"
- System checks: are all blocking steps complete?
- If NO → shows message "Complete checklist before starting load" with list of remaining steps
- If YES → load status updates normally

**The Dispatch Ready indicator:**
- On the Load detail screen, you'll see "Dispatch Ready" (green) or "Blocked" (red)
- Blocked state shows which steps are incomplete
- Once all blockers are done, it flips to "Dispatch Ready"

<Callout variant="tip" title="Pro Tip">
Only mark truly critical steps as blockers. Too many blockers frustrates drivers. Use blockers for: safety inspection sign-off, BOL verification, hazmat acknowledgment. Make "nice to have" steps optional.
</Callout>

## Auto-Start Rules

Dispatch Checklists can trigger automatically based on different events:

| Trigger Event | When It Fires | Example Use |
|--------------|---------------|-------------|
| ON_DISPATCH_CREATE | When a load is created and assigned to a driver | Pre-trip inspection, load acceptance |
| ON_DISPATCH_DEPART | When driver marks load "In Transit" | Post-departure verification |
| ON_DISPATCH_DELIVER | When driver marks load "Delivered" | Post-trip inspection, POD capture |

### Setting Up Auto-Start

<StepFlow>
  <StepFlow.Step title="Go to Automation">
    Navigate to **Workflows → Automation**.
  </StepFlow.Step>
  <StepFlow.Step title="Find the Pre-Trip Inspection recipe">
    Look for the "Pre-Trip Inspection" card in the Recipes section.
  </StepFlow.Step>
  <StepFlow.Step title="Select your checklist">
    Choose which Dispatch Checklist should run when loads are dispatched.
  </StepFlow.Step>
  <StepFlow.Step title="Enable the rule">
    Toggle the rule to Active.
  </StepFlow.Step>
</StepFlow>

Now every time you dispatch a load, the checklist auto-starts for the assigned driver.

### Conditional Auto-Start

You can add conditions to control when checklists trigger:

- **Commodity type** — Only start hazmat checklist for hazmat loads
- **Customer** — Extra verification for high-value customers
- **Driver experience** — Extended checklist for new drivers, streamlined for veterans

Conditions use simple key-value matching (e.g., "Only if commodityType = HAZMAT").

## Driver Experience

When you dispatch a load with a Dispatch Checklist enabled:

1. **Push notification** — Driver receives: "Pre-Trip Checklist for Load #1234 ready"
2. **Checklist card on dashboard** — Shows progress bar and "Start" button
3. **Step-by-step completion** — Driver taps each step, completes the requirement
4. **Inspection mode** — For vehicle inspections, enters full-screen mode: one item at a time, PASS/FAIL buttons, auto-advance
5. **Progress saved** — Can pause and resume; progress persists
6. **Completion** — Shows summary: "12 passed, 0 failed" with timestamp
7. **Load unlocked** — Can now mark load "In Transit"

### Mobile Inspection Mode

For vehicle inspections, the mobile app enters a focused full-screen mode:

- Large PASS (green) and FAIL (red) buttons
- One inspection item at a time
- Auto-advances on PASS
- On FAIL: camera opens for photo, notes field appears
- Progress counter: "4 of 12"
- No distractions — driver focuses on the inspection

## Viewing Completed Checklists

All completed checklists are saved with full audit trail:

1. Go to **Workflows → Instances**
2. Filter by status (Completed, In Progress, Blocked)
3. Click any instance to view:
   - Who completed each step
   - When each step was completed
   - Photos, signatures, and form data captured
   - Any failed inspection items and their resolutions

This data is available for DOT audits, insurance claims, and customer disputes.

## Important Notes

**Checklists are immutable once started:**
When a checklist starts, it takes a snapshot of the template at that moment. If you later edit the template, running checklists aren't affected — they use the version from when they started. This ensures consistency and audit compliance.

**One checklist per load:**
Each dispatch can have one active checklist at a time. If you need multiple verification workflows, combine the steps into one comprehensive checklist with phases.

**Blocking steps vs. required steps:**
- **Blocking steps** prevent load status changes until completed
- **Required steps** must be completed to mark the checklist "done" but don't block load progress
- Use blocking for safety-critical items; use required for documentation items
